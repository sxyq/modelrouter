# 长程 Agent 的任务级成本路由

**全场主线**：长程 Agent 的费用由完整执行轨迹决定。真实调用数据先展示推理档位、缓存和单次调用成本这三个变量，再用四篇论文说明它们分别如何进入模型路由与 Agent 成本问题，最后提出研究问题：在任务开始前，预测一个配置的整条轨迹是否值得，能不能比在线学习或盲分配更有效。

### P4｜KV Cache 命中与多 Agent 的共享前缀
**本页目的**：解释 KV Cache 的命中原理，并指出多 Agent 链路下前缀缓存的共享价值与冲突。
**口播稿**：一次调用中，每层、每个头、每个 token 都会算出一对 K/V 并缓存。后续生成只需算新 token，前面读缓存就能省钱。在多 Agent 场景中，默认独立推理会让一样的提示词在显存各存一份；开启前缀缓存（如 RadixAttention）后，相同前缀只算一次。还要区分 KV 共享和语义缓存，后者复用的是答案。如果多个 Agent 共享这段长前缀，云端 API 的固定前缀未命中就按完整输入计费；本地 8 份 4,000 token 的复制约 4.7GB，页面标注占 16GB 卡的 51%。前缀必须逐 token 对齐，提示词或工具定义发生变化，复用收益就会消失。
**讲图/交互**：先看上半部分，点击页面任意处重播动效，看 K/V 如何逐层缓存、命中和失效。再看下半部分的三块说明，对比独立推理、前缀缓存和语义缓存；接着看 Agent A、B、C 的共享比例条，最后指向云端 API、本地自建和 CacheScout 的 scope 数据卡。
**过渡**：除了缓存，还有一个重要变量是模型自己的推理档位。

### Q&A（预留问题与要点）

1. **预测长程任务的总 token 和成本是非常不准的，预测误差不会导致路由失效吗？**
   - 回答要点：确实，事前 token 预测相关性很低，方差极大。因此，我们的预测器不能做单一点估计，必须输出成本分布和分位数（CDF），决策时使用 P90 等做保守估计。同时，我们会做误差敏感性扫描，只要预测器比盲分配更有鉴别力就能产生价值，不需要它达到完美的理论最优。

2. **你提到模型单次调用的价格可能和任务级的 $/success 反转，为什么会有这种反转？**
   - 回答要点：单价便宜的模型如果在长程任务中频繁失败、陷入死循环、或者反复输出大量无用的 reasoning token 和工具调用，它在整条轨迹累积的成本会极高。这种 failure-aware 记账已被学术界提及，所以一把过的更贵模型，其任务级的单次成功平均成本（$/resolved）反而可能更低。

3. **你们这个想法和 TRACE-Router 有什么本质区别？**
   - 回答要点：决策粒度一致（都是任务启动时选择一次），但方法和目标不同。TRACE 用的不需事前预测的在线 UCB（Contextual bandit），且用延迟作为成本代理；而我们是明确做事前（ex-ante）的多目标预测（成功概率、token、美元），并在硬性的质量约束下寻找成本 P90 最小的“模型 × 推理档位”配置。TRACE-Router 将是我们的直接对照基线。
