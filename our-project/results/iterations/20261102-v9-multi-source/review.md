这里每列分母都是该来源所选 8 条候选。7 个可进一步比较的 SWE-smith 状态具有历史环境与测试依据，其中只有 2 个的精确基础镜像现仍在本机；其余缺镜像，不计本轮实测。Mido 额外一条保留真实历史，但原 `initial_verifier_exit_code=4`，不能据此认定原验证可信。Inspect 2 条仅说明决策前阶段覆盖，不把下一次读取或最终 Episode 成功变成一步偏好。

- SWE-smith：旧清洗器将 `owner__repo.commit.fault` 的仓库只写成 owner，且未记录原轨迹行和消息截止。原入口现保留 owner/repo、短 commit 标识、故障身份、原分片、轨迹行和截止点。短 commit 标识不冒称完整 Git commit；不同前缀保留不同状态身份，任务数仍按任务身份计。
- SWE-Gym：旧清洗器只保留 400 字符题面、200 字符测试摘要及 `has_test_patch`。本轮 8 条仅可用于目录和字段观察，完整题面、测试补丁、完整测试 ID、环境版本与 Agent 历史均不能从摘要恢复。
- SWE-rebench：旧清洗器未保留 base commit、镜像、安装配置、完整测试 ID、补丁和逐仓库许可证。8 条因此是复现条件未知的任务候选，不是已证实无效的公开任务，更不是错误偏好。

在原 `env_memory.py` 的两个清洗函数中保留完整题面；环境版本、镜像和安装配置放在来源证据；F2P/P2P、测试补丁和参考补丁保留在 `ground_truth_outcome`，参考补丁不进入决策前输入。原摘要字段继续存在，Trainer 语义不变。嵌套 Parquet 字段沿原 pandas 行转换为 JSON 数据，不增加依赖。`router_data/env_memory.py` 与 `router_data/tra.py` 的重复主体已换为原包入口的薄导入，正式实现各保留一处，Git 历史可恢复旧主体。

当前官方 SWE-rebench 数据卡明确 CC-BY-4.0，并提供每条任务的 `license`。来源注册、已有 manifest、许可证统计及说明已同步。历史登记 revision 对应 README 返回 `Entry not found`，因此这里只确认当前官方许可，不声称还原了旧版本数据卡。原始文件、预览 JSONL、历史数据统计和已有字节摘要没有重新计算或改写。

## 4. 两项真实离线环境结果

沿原 mini-SWE-agent 2.4.6 `DockerEnvironment` 与两个已有 amd64 基础镜像，先运行原范围，再施加保存的 SWE-smith **故障补丁**并恢复所选截止前工具动作，最后运行相同原测试 ID。仅追加 pytest `-rA` 输出单项状态，不改测试内容或范围。没有参考修复补丁进入模型输入，也没有任何模型请求。

| 任务及恢复状态 | 原来源版本原测试 | 故障版本 F2P | 故障版本 P2P | 单项未知 / 环境错误 |
|---|---:|---:|---:|---:|
| Records，Sol历史 cutoff3，Modify | 24/24 通过 | 1/1 失败 | 23/23 通过 | 0 / 0 |

两个任务原范围均实际可执行，故障前后符合固定 F2P/P2P 的预期行为；历史工具退出码恢复一致。镜像未安装缺项：它们本身没有 `rg`，历史调用会返回 127，这是实际工具反馈，不是原测试安装失败。原范围四次调用证据保留于 [environment](environment/)，包括参考/故障验证文本、固定测试 ID 状态；完整历史恢复输出仅留本机，不提交公开仓库。它们是离线环境结果，不是官方 Agent 基准成绩。

SWE-Gym / SWE-rebench 实际任务执行各 0。缺完整本地任务及历史；Gym 测试摘要已截短，rebench 镜像、版本、安装和测试字段未保留，不能据 repo 猜镜像或根据已有他题镜像冒充环境。不访问服务器取全量，也不下载或构建镜像。

## 5. 下一批数据与当前项目结论

当前实际可开展小量采集的仍是 SWE-smith 已有 Train 子集，优先这两条完整历史、明确故障、原测试可信且镜像已在本机的状态。保留此前 19 条合法偏好和其他已证实质量状态；Mido 原验证异常及缺工具/缺环境材料只保留观察，不删除整个来源。

下一批完整任务资产优先补齐 SWE-rebench V2：当前官方字段明确包含 image_name、install_config、完整 F2P/P2P、base commit 与逐仓库许可，更适合按原字段定位环境；这一判断是**资产准备优先级**，不是已证明该来源标签产出更高。SWE-Gym 同时保留为 Python 对照来源，但本机没有 Agent 历史。获得完整任务/历史后，先完成真实环境与已有 Test 任务交叉识别，才有依据决定训练质量采集是否主要迁移；目前没有足够结果宣布替代来源整体更优，也没有新增数据可直接启动微调。

本轮没有新增付费授权，P3 未执行。若后续单独授权，沿原 Provider 配置止于 `/v1` 的 Chat base_url，最多两次 Luna 完整动作生成，再从确实可恢复的每源各一题最多六次 Sol/Luna 单步生成；缺来源状态的额度保留，不转移。原一步全范围通过定义、教师关闭、模型身份/Usage/费用记录不变。固定测试修复集合与回归只能作为独立探索证据，不能并入旧 S1。正式 K=3、Native Effort、STEP_001 精确实体及动态收益缺口均保持。

通俗地说：这次把“能用来继续比较的状态”“只有任务摘要的材料”和“已经有真实赢家的答案”分清了，并实测确认两个环境确实能区分故障前后。数据准备更有用，但 Router 没有获得新赢家监督，没有变更参数，尚不能说选择能力或动态收益提高。

两个自有容器均已移除，原基础镜像保留；临时执行脚本用完删除。旧 Trainer/tests、私人账本、历史删除、Fig.2、原训练材料及其他运行数据均保留。没有 PR、CI 或服务器同步。
