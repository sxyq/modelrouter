# F6: 2025–2026 补漏（survey / benchmark / bandit / tool-use / code cascade / 厂商 $ 证据）

## Findings

### [1] TMLR 2026 路由综述 Dynamic Model Routing and Cascading 把范式分为 difficulty / preference / clustering / UQ / RL / multimodality / cascading，并沿 when–what–how 三维刻画；分类仍是推理时「选一个模型/走 cascade」，未出现「长程 agent 整任务预算预测」分支
- quote: "This survey provides a systematic analysis of multi-LLM routing and cascading approaches, focusing on systems that route queries across a pool of independently trained LLMs at inference time. We cover diverse routing paradigms, including query difficulty, human preferences, clustering, uncertainty quantification, reinforcement learning, multimodality, and cascading… characterizes routing systems along three dimensions: when decisions are made, what information is used, and how they are computed."
- url: https://arxiv.org/abs/2603.04445
- source_type: primary（TMLR 2026 综述；Huawei/ADAPT 资助）
- published: 2026-02-23 (v1); v3 2026-08-30
- confidence: high
- 粒度：综述对象=多 LLM 推理时查询路由；是否含 agent 任务级成本：摘要与分类未见该轴；与任务级 $/success 关系：可作「查询级 routing 已充分综述、agent 任务级仍是开放面」的引用。

### [2] TwinRouterBench 直指 RouterBench 类 one-shot 基准的缺口：970 条 agent 中途 router-visible 前缀（SWE-bench/BFCL/mtRAG/QMSum/PinchBench）+ SWE-bench Verified 动态 track，成功用官方 resolve、成本用 realized API spend
- quote: "existing router benchmarks evaluate routers only on one-shot prompts… We introduce TwinRouterBench, a step-level routing benchmark with two tracks. The static track provides 970 router-visible prefixes from 520 instances… The dynamic track supplies a harness that runs routers on the full 500-case SWE-bench Verified suite… success is measured by official task resolution and realized API spend."
- url: https://arxiv.org/abs/2605.18859
- source_type: primary
- published: 2026-05-14 (v2 2026-05-22)
- confidence: high
- 粒度：agent 步级前缀 + 整任务动态执行；是否预测成功/调用数：静态 track 用 downgrade-and-cascade 得 target tier，动态 track 事后再记 spend；是否任务总成本：是（live $ 与 resolve）；与 F1 RouterBench 关系：RouterBench=11 模型×8 数据集 one-shot；Twin 是 2026 年后继，最贴近本课题实验设计。

### [3] Switchcraft 自称首个面向 agentic tool calling 的模型路由器：DistilBERT 在线选最低价正确模型，82.9% 准确、成本 −84%、每百万 query 省 >$3,600；并报告「名义更便宜模型因 reasoning token 更多反而总成本更高」
- quote: "We present Switchcraft, the first (to the best of our knowledge) model router optimized for agentic tool calling… achieves 82.9% accuracy… while reducing inference cost by 84%, saving over $3,600 per million queries. We find that larger models do not consistently outperform smaller ones on tool-use tasks, and that nominally cheaper models can incur higher total cost due to token-intensive reasoning."
- url: https://arxiv.org/abs/2605.07112
- source_type: primary
- published: 2026-05-08
- confidence: high
- 粒度：单次 tool-call 请求（inline），非多步整任务；是否预测成功：正确性约束下的最低价；是否任务总成本：请求级 $；与成本反转：双重证据——(a) 大≠总是更好；(b) 单价便宜≠总成本便宜（reasoning token）；局限：非 SWE 长程。

### [4] WISERouter 把 LLM 路由写成带 workload 总预算约束的 contextual MAB：Offline/Online 两模式，WR-Online 有 O(√T) regret；在 RouterBench 与 SWE-Bench 上验证预算遵守与性能
- quote: "we formulate LLM routing as a constrained contextual multi-armed bandit problem and introduce WISERouter… prove that WR-Online achieves a sublinear regret bound of O(√T)… Empirical results on RouterBench and SWE-Bench demonstrate that… WR-Offline surpasses existing baselines in performance under a fixed budget…"
- url: https://arxiv.org/abs/2607.23765
- source_type: primary
- published: 2026-07-26
- confidence: high
- 粒度：query→模型分配（含 SWE-Bench 设定）；是否预测成功：bandit reward 隐式学效用；是否任务总成本：workload 级预算约束（非逐任务 $/success 公式）；bandit 线：相对 MetaLLM/LLM Bandit 的更新版本。

### [5] UniScale（ICML 2026）把「跨模型路由 × 单模型 test-time scaling」并成 Unified Inference Scaling，用 LinUCB 在线联合优化——是模型×档位联合动作空间最接近的会议接收工作
- quote: "we introduce Unified Inference Scaling (UIS), which unifies model routing and TTS in a single optimization space… UniScale, an online framework that models adaptive UIS as a contextual multi-armed bandit problem and learns inference policies via LinUCB." / Comments: "Accepted at the 43rd International Conference on Machine Learning (ICML 2026)"
- url: https://arxiv.org/abs/2605.30898
- source_type: primary（ICML 2026 接收）
- published: 2026-05-29
- confidence: high
- 粒度：单请求的 (model, TTS 强度)；是否预测成功/整任务 $：摘要强调质量–成本 trade-off，未声明事前整任务美元预测；与 F3 RTR/effort 档位关系：RTR=离线分类 (model,strategy)；UniScale=在线 bandit 联合。任务级 agent 长程仍未覆盖。

### [6] CodeRescue（ByteDance，已撤稿）把 coding agent 失败后动作形式化为「便宜模型再恢复 vs 升级强模型」的 recovery routing + Conformal Risk Control；主设定下一点解率超 always-escalate 且平均恢复成本仅 35%
- quote: "we formulate this post-failure decision as recovery routing over heterogeneous actions… one CRC-calibrated frontier point exceeds always-escalate solve rate while using 35% of its mean recovery cost." / Comments: "Withdrawn at the request of ByteDance…"
- url: https://arxiv.org/abs/2607.19338
- source_type: primary（撤稿 v2；引用需标注 withdrawn）
- published: 2026-07-21; withdrawn 2026-07-30
- confidence: medium-high（撤稿，方法细节仍可从 v1 摘要核实）
- 粒度：coding 基准失败后的单次决策（非全程逐步）；是否预测成功：监督 router 从 execution rollouts 学；是否任务总成本：conformal 控边际期望成本；与 cascade 关系：明确批评「cheap-first 二元 cascade」不够，需三动作（再试便宜/升级/…）。

### [7] Bayesian Self-Escalation 把「生成中途发现会失败→交给更强模型」写成 Bayesian optimal-stopping：competence posterior + 时变阈值；MBPP 上 Qwen2.5-Coder 1.5B→7B 验证升级前沿在同成本下支配 post-hoc 路由
- quote: "an agent that recognises, during its own reasoning, that it is unlikely to succeed and transfers control to a stronger model… Bayesian optimal-stopping problem over a learned competence posterior… escalation frontier dominates post-hoc routing at equal cost"
- url: https://arxiv.org/abs/2608.24087
- source_type: primary
- published: 2026-08-25
- confidence: high
- 粒度：单次生成内的步/时刻（intra-generation）；是否预测成功：是（事前学 competence 后验，在线更新）；是否任务总成本：理论+同成本前沿，非多步 SWE 任务美元表；与 SWE-Router/TACIT 关系：第三种干预时点（生成中途 vs 前缀后 vs 一次性 handoff）。

### [8] Early-Abort probe cascade 用 hidden-state 线性探针从第一轮预测 episode 最终失败，recall 控制多轮 early stop：90% recall 下 TextCraft/WebShop 生成 token 降 60.2%/54.9%，比单门基线多省 1.5–8.8× 算力
- quote: "Lightweight linear probes on internal activations predict eventual task failure from the first interaction round… reduce generated tokens by 60.2% on TextCraft and 54.9% on WebShop at 90% recall, while retaining savings of 45.0% and 41.5% at 95% recall."
- url: https://arxiv.org/abs/2607.06503
- source_type: primary
- published: 2026-07-07 (v2 2026-07-16)
- confidence: high
- 粒度：agent episode 早期轮次中止；是否预测成功：是（失败探针）；是否任务总成本：省 token/算力，非跨模型选型；与任务级成本：属「负样本弃跑」支线，可与路由叠加。

### [9] BudgetMLAgent（AIMLSystems'24）在 MLAgentBench 上用 Gemini 基座 + GPT-4 cascade/expert：每次 run 成本 $0.931→$0.054（−94.2%）且成功率 22.72%→32.95%——学术侧少见的 $/run 与成功率同向改善
- quote: "With 94.2% reduction in the cost (from $0.931 per run cost averaged over all tasks for GPT-4 single agent system to $0.054), our system is able to yield better average success rate of 32.95% as compared to GPT-4 single-agent system yielding 22.72%"
- url: https://arxiv.org/abs/2411.07464
- source_type: primary（会议短文）
- published: 2024-11-12 (v2 2025-01-08)
- confidence: high
- 粒度：整条 ML 工程任务 run；是否预测成功：profiling+级联+专家调用，非显式成功预测器；是否任务总成本：是（$/run）；与成本反转：便宜组合同时更便宜且更成功（任务级 dollar 证据，基准较弱、模型代际旧）。

### [10] COPE（TMLR 2026）让小/大模型轮流当 planner/executor 做多级 plan-cascade，覆盖数学/代码/agent 任务，宣称接近大闭源模型性能同时大幅降 API 成本
- quote: "A planner model first generates a plan that serves as a lightweight intermediate… Small and large models take turns acting as planner and executor, exchanging plans in a multi-stage cascade… achieving performance comparable to large proprietary models, while drastically reducing the inference API cost." / "Accepted at TMLR 2026"
- url: https://arxiv.org/abs/2506.11578
- source_type: primary（TMLR 2026 接收）
- published: 2025-06-13 (v5 2026-08-25)
- confidence: high
- 粒度：任务级多阶段协作（非逐步动态路由）；是否预测成功：无显式成功头；是否任务总成本：API 成本对比；与 cascade 线：plan 作轻量中间物的 code-agent 邻近工作。

### [11] 厂商证据（Anthropic，2025-09-29）：Claude Sonnet 4.5 在与 Sonnet 4 **同价**（$3/$15 per M tokens）下大幅提能力，官方写明 drop-in replacement with much improved performance for the same price——「同价更强」而非「更贵模型 $/success 更低」
- quote: "Pricing remains the same as Claude Sonnet 4, at $3/$15 per million tokens." / "Sonnet 4.5 is a drop-in replacement that provides much improved performance for the same price."
- url: https://www.anthropic.com/news/claude-sonnet-4-5
- source_type: secondary（厂商发布博客；可引用，须标注 vendor）
- published: 2025-09-29
- confidence: high（价格与表述可信；无 $/task 表）
- 与任务级成本：支持「代际更强且单价不升」的长期趋势；不直接给某任务上贵模型更便宜的翻转率。

### [12] 厂商证据（OpenAI，2025-08-07）：GPT-5 相对 o3(high) 在 SWE-bench Verified 更高分（74.9% vs 69.1%）且更省——output token −22%、tool calls −45%——任务级 token/工具调用效率的「更好且更省」样本
- quote: "relative to o3 at high reasoning effort, GPT-5 uses 22% fewer output tokens and 45% fewer tool calls." / Pricing: "GPT-5 is priced at $1.25/1M input tokens and $10/1M output tokens, GPT-5 mini… $0.25/$2, and GPT-5 nano… $0.05/$0.40."
- url: https://openai.com/index/introducing-gpt-5-for-developers/
- source_type: secondary（厂商开发者博客；可引用，须标注 vendor）
- published: 2025-08-07
- confidence: high（token/tool 数为自报；美元需按价目表再乘）
- 与任务级成本：厂商侧「更强模型在 agent 任务上 token/工具调用反而更少」的直接表述；未给完整 $/resolved 表。

### [13] Bandit 侧周边（非任务级主证据）：MetaLLM（MAB 动态选 LLM）、LLM Bandit（偏好条件路由）、GreenServ（MAB+能耗，RouterBench 上 16 模型）、Symphony-Coord（多 agent 子任务 LinUCB）——在线学习路由已铺开，但 reward 多为请求质量/能耗，不是整任务 $/success
- quote: MetaLLM: "By framing the selection problem as a multi-armed bandit, MetaLLM balances prediction accuracy and cost efficiency under uncertainty." / GreenServ: "compared to random routing, GreenServ achieved a 22% increase in accuracy while reducing cumulative energy consumption by 31%… evaluated GreenServ with RouterBench" / Symphony-Coord: "transforms agent selection into an online multi-armed bandit problem… adaptive LinUCB selector"
- url: https://arxiv.org/abs/2407.10834
- source_type: primary
- published: MetaLLM 2024-07 / v2 2025-04; GreenServ 2026-01; Symphony-Coord 2026-01/02
- confidence: high（摘要级核实；未逐篇读实验表）
- 与任务级成本：bandit 工具箱成熟；「任务级成功×多步花费」作为 reward 的系统工作仍少见（WISERouter 最接近）。

### [14] 综合判断（本角度）：2025–2026 补漏后，查询级 routing 的 survey/benchmark/MAB 已厚，agent 侧出现 TwinRouterBench（步级+$）、Switchcraft（tool-call $）、CodeRescue/Self-Escalation/Early-Abort（失败后/中途/弃跑）等，但仍未见同行评审工作以「事前预测整任务成功概率×调用数×token×$」为联合目标并在质量约束下选 (模型×档位)
- quote: TwinRouterBench 用事后 realized spend；Switchcraft 单请求；WISERouter workload 预算；UniScale 请求级 UIS；SWE-Router/TACIT（F2）决策点有限；Together DeepSWE（F3）是厂商任务级 $。
- url: https://arxiv.org/abs/2605.18859
- source_type: primary（综合）
- published: 2026-09-15（检索结论日）
- confidence: medium-high
- 结论：研究空间仍在，但「benchmark + 失败后路由 + 在线 bandit」正在快速收敛；新贡献需瞄准事前联合预测与 $/success 反转的系统测量，而非再做一个 one-shot router。
