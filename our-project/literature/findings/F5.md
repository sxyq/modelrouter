# F5 任务基准与测量基础设施：可行性与混杂

## Findings

### [1] SWE-bench 提供大规模可自动判定的 repo 级任务，成功判据是 FAIL_TO_PASS + PASS_TO_PASS 单元测试
- **claim**: 2,294 个来自 12 个公开 Python 仓库 GitHub issue 的软件工程问题；任务是给 codebase + issue 描述，让模型编辑代码。评测：先看 FAIL_TO_PASS 测试是否通过（表示 issue 被解决），再看 PASS_TO_PASS 是否通过（表示未破坏既有功能）；两组都过才算完全解决。论文写明：闭源与开源模型在发布时解决率极低（Claude 2 最佳仅 1.96%）。
- **url**: https://arxiv.org/abs/2310.06770
- **source_type**: primary paper (ICLR 2024)
- **published**: 2023-10 (v1), 2024-11 (v3)
- **confidence**: high
- **notes**: 官方 leaderboard / Docker harness 已开源（SWE-bench 组织）。**推断**: 多模型重放可通过同一 harness + 不同 LLM 后端实现；基准本身不强制记录 token/费用字段，费用需自测。

### [2] SWE-bench Verified：人工清洗后的 500 子集，明确指出原版评分噪声与环境不稳定
- **claim**: OpenAI 与 SWE-bench 作者合作，用 93 名职业开发者标注 1,699 条原版测试集样本，剔除问题描述模糊、FAIL_TO_PASS 过窄/无关、其它重大问题的样本，得到 500 条 Verified（“supersedes the original SWE-bench and SWE-bench Lite”）。标注流程：每样本 3 人独立标，取最高严重度；原版约 38.3% 被标为问题描述不充分、61.1% 被标为单元测试可能拒掉合法解。新 harness 用容器化 Docker 改善环境可复现性。验证 GPT-4o 在最佳 scaffold 上从原版 16% 升至 33.2%，且难度分桶内表现也提升。
- **url**: https://openai.com/index/introducing-swe-bench-verified/
- **source_type**: primary technical blog + dataset release
- **published**: 2024-08 (updated 2025-02)
- **confidence**: high
- **notes**: 对路由实验的直接含义：在原版 SWE-bench 上做 cost-aware 模型选择，会把评分噪声和环境故障误当成模型差异。Verified 更适合做主评测，但样本量 500 对“每任务多模型全量重放”的费用仍可观。污染风险（公开 GitHub 预训练污染）在讨论中被点名。

### [3] SWE-Gym：面向训练的 2.4k 交互式任务环境，公开发布 agent trajectories，含可执行 Docker 镜像
- **claim**: SWE-Gym 含 2,438 个真实 Python 任务实例（11 仓库），每个含 codebase、可执行 runtime、单元测试与自然语言任务描述；Lite 划分 234 条。官方声明公开发布环境、模型与 agent trajectories；预构建 Docker 镜像在 `xingyaoww/sweb.eval.x86_64` 前缀下；HuggingFace 提供数据与模型。论文写明：用 <500 条来自 GPT-4o 与 Claude 3.5 Sonnet 采样的交互轨迹微调后，在 SWE-bench Verified 上 +14% 绝对提升（32B OpenHands agent）。
- **url**: https://arxiv.org/abs/2412.21139 ; https://github.com/SWE-Gym/SWE-Gym
- **source_type**: primary paper (ICML 2025) + official README
- **published**: 2024-12 (v1), 2025-06 (v2)
- **confidence**: high
- **notes**: 这是目前最接近“公开完整交互轨迹 + 可重放环境”的 SWE 资产之一。**推断**: 轨迹可用于离线估计“弱模型失败模式”，但公开轨迹仅覆盖少数模型（GPT-4o、Claude 3.5 Sonnet 等采样者），不是全模型成本标签；token/美元成本字段未在 README 中列为一等公民，需重放时自行埋点。**混杂**: 动态交互轨迹在温度非零时不可逐字重放；环境本身 Docker 化但仍受镜像可用性影响。

### [4] SWE-Rebench：21k+ 自动采集任务 + 持续无污染评测，论文写明 Verified 存在污染导致分数膨胀
- **claim**: 自动化流水线从多样 GitHub 仓库持续抽取交互式 Python SWE 任务；公开数据集超过 21,000 条，适合 SWE agent 的大规模 RL；同时用连续采集的新鲜任务构建无污染评测集。论文写明：与 SWE-bench Verified 对比后，部分语言模型在 Verified 上的表现可能因污染而被高估。
- **url**: https://arxiv.org/abs/2505.20411
- **source_type**: primary paper (NeurIPS 2025)
- **published**: 2025-05 (v1), 2025-11 (v2)
- **confidence**: high
- **notes**: 对成本路由的直接含义：用 Verified 做长期路由策略评估会偏向“见过题目”的模型；Rebench 的“任务持续供给 + 新鲜切片”适合跟踪闭源 API 更新后的路由泛化。**推断**: 规模更大 → 全量多模型重放成本线性上升，需要分层采样或预筛选难度区间。

### [5] Terminal-Bench：约 100 条终端任务 + 沙箱 harness，每题带测试脚本与 oracle 解，适合 CLI 长程任务
- **claim**: README 写明：Terminal-Bench 由任务数据集 + 把语言模型接到终端沙箱的执行 harness 组成；当前 beta 约 100 任务。每个任务包含英文 instruction、验证是否完成的 test script、以及 reference (“oracle”) solution。评测通过 CLI（如 `tb run --agent terminus --model … --dataset-name terminal-bench-core --dataset-version 0.1.1`）接入多模型；Docker 作为沙箱前提。ICLR 2026 引用条目确认定位为 “Hard, Realistic Tasks in Command Line Interfaces”。
- **url**: https://github.com/harbor-framework/terminal-bench-1 (原 laude-institute/terminal-bench)
- **source_type**: official GitHub README + citation block
- **published**: beta era ~2025; paper ICLR 2026
- **confidence**: high
- **notes**: **推断**: 测试脚本 + oracle 可做成功判据自动化；token/费用仍需 harness 外层统计。~100 题量级下，多模型全量重放在预算上可行，但统计功效弱于 SWE 系。环境是 Docker 终端，可复现性好于真实网站类基准。

### [6] WebArena：812 级别长程 web 任务，功能正确性判定；人类 78.24% vs GPT-4 最佳 14.41%
- **claim**: 构建四个真实网站域（电商、论坛、协作开发、内容管理）的可复现环境；基准任务 “diverse, long-horizon”；评测聚焦功能正确性。最佳 GPT-4 agent 端到端成功率 14.41%，人类 78.24%。代码、数据、环境复现资源公开。
- **url**: https://arxiv.org/abs/2307.13854
- **source_type**: primary paper
- **published**: 2023-07 (v1), 2024-04 (v4)
- **confidence**: high
- **notes**: **推断**: 成功与否可自动/半自动判定（功能正确性检查器），但环境需自建多容器站点，运维成本高于 SWE Docker 评测；公开“完整轨迹”不是该论文的重点。**混杂**: 自托管网站版本漂移可能导致跨年复现差异（README 提供复现资源，但未在摘要中断言零漂移）。VisualWebArena / OSWorld 系扩展未在本轮逐篇 WebFetch，规模与判据以各自论文为准（OSWorld 见下）。

### [7] OSWorld：369 条真实桌面/OS 任务，execution-based 自定义评测脚本，环境搭建重
- **claim**: 首个面向多模态 agent 的可扩展真实计算机环境（Ubuntu/Windows/macOS）；基准 369 任务，覆盖真实 web 与桌面应用、文件 IO、跨应用工作流；每题含详细初始状态配置与 custom execution-based evaluation script 以支持可靠、可复现评测。人类 >72.36%，最佳模型 12.24%（论文发布时）。
- **url**: https://arxiv.org/abs/2404.07972
- **source_type**: primary paper
- **published**: 2024-04 (v1), 2024-05 (v2)
- **confidence**: high
- **notes**: 成功判据明确（脚本化），但 VM/GUI 环境启动慢、并行度受限 → **推断**: 对“大规模多模型成本曲线”不经济，更适合小样本定性对照。轨迹字段（token/费用）未在论文摘要中承诺。

### [8] τ-bench / τ²-bench：数据库终态对比 + pass^k 可靠性指标；用户模拟器引入随机性
- **claim**: τ-bench：agent 在领域 API 工具与政策约束下与模拟用户对话；高效且忠实的评测是比较对话结束后的数据库状态与标注目标状态；提出 pass^k 度量多次试验的一致性；GPT-4o 等在 retail 上 pass^8 <25%，说明行为不一致。τ²-bench（后续）：Telecom 双控制域（Dec-POMDP），agent 与用户共用工具改共享状态；组合式任务生成器程序化生成可验证任务；受约束的 user simulator；实验显示从 no-user 切到 dual-control 后性能显著下降。
- **url**: https://arxiv.org/abs/2406.12045 ; https://arxiv.org/abs/2506.07982
- **source_type**: primary papers
- **published**: 2024-06; 2025-06
- **confidence**: high
- **notes**: 成功判据是状态差分而非自由文本评分 → 评分噪声低于开放 web 任务。**混杂（论文写明方向）**: 依赖 LLM 用户模拟器与多次采样（pass^k），天然要求 k 次重复实验，费用约为单次的 k 倍；模拟器温度与 LLM 版本会改写对话轨迹。**推断**: 很适合做“成本-可靠性”曲面（cost vs pass^k），但用户模拟器侧成本需单独记账。

### [9] AgentBench / BFCL / ToolBench / GAIA / MultiChallenge：能力维度不一，测量基础设施与成本字段普遍不完整
- **claim**:
  - AgentBench：8 个不同环境的多维基准，评测 LLM-as-Agent 的推理与决策；数据集、环境与评测包公开。论文写明商用 LLM 与许多 ≤70B 开源模型之间差距大，失败主因是长程推理、决策与指令跟随。
  - GAIA：466 道真实世界问题（推理、多模态、web 浏览、工具使用）；公开问题，但保留其中 300 道的答案用于 leaderboard；人类 92% vs GPT-4+plugins 15%。
  - ToolBench / BFCL：工具/函数调用基准（本轮未逐篇 WebFetch 原文，仅作对照）；**推断**: 其评测多为单轮/短程 tool-call 正确性，不含任务级 token/费用原生字段，不适合作为“长程成本路由”主战场，可作前置能力筛选。
  - MultiChallenge（AI2）：多轮对话一致性类基准；本轮未能稳定抓取 arXiv/OpenReview 原文，规模与字段未核实 → 见 Dead ends。
- **url**: https://arxiv.org/abs/2308.03688 ; https://arxiv.org/abs/2311.12983
- **source_type**: primary papers (AgentBench, GAIA); 对 BFCL/ToolBench/MultiChallenge 为部分推断
- **published**: 2023-08; 2023-11
- **confidence**: medium (AgentBench/GAIA: high; 其余: low–medium)
- **notes**: 对任务级成本路由：GAIA 答案部分隐藏 → 本地实验只能用公开 split；AgentBench 多环境但任务粒度偏短/混合，不是统一长程设定。

### [10] 轨迹/日志侧：SWE-Gym 与 SWE-smith 明确公开轨迹；OpenHands 评测栈可多模型重放；token/成本字段通常缺失
- **claim**:
  - SWE-Gym README/论文写明公开 agent trajectories 与多 scaffold 复现路径（OpenHands、MoatlessTools）；Docker 镜像预构建。
  - SWE-smith（2504.21798，本轮抓取到摘要）：50k 训练实例、128 仓库，开源 procedure / task instances / trajectories / models；SWE-agent-LM-32B 在 Verified 上 40.2% Pass@1。
  - OpenHands 官方 README 现定位为 Agent Canvas：本地/Docker/VM 多 backend，可接任意 LLM，可 ACP 接 Claude Code 等；**推断**: 其 evaluation harness 支持换模型跑同一 SWE 任务集，适合自建 token/费用埋点后做多模型成本重放。OpenHands 长期发布的“公开对话轨迹数据集”与商业 provider usage logs 本轮未逐一核实文件级 schema。
- **url**: https://github.com/SWE-Gym/SWE-Gym ; https://arxiv.org/abs/2504.21798 ; https://github.com/OpenHands/OpenHands
- **source_type**: official READMEs + primary abstracts
- **published**: 2024-12–2025
- **confidence**: high (SWE-Gym/SWE-smith 轨迹公开); medium (OpenHands 多模型重放为推断+README 佐证)
- **notes**: **关键缺口（推断）**: 公开 agent 轨迹通常含 observation/action 序列，但 **不保证** 含 per-call input/output tokens、美元成本、墙钟延迟；API provider usage logs（OpenAI/Anthropic 控制台导出）有 token 与费用，但不公开、不可共享，且无法跨 provider 统一。成本路由实验必须自建统一日志层（task_id, model, step, tokens_in/out, $, latency, success）。

### [11] 成本感知路由论文现状：chat/LLM 路由成熟（RouteLLM 等），任务级 agent 路由在上述基准上的公开工作稀少
- **claim**: RouteLLM 写明：在强/弱模型间用偏好数据训练 router，优化成本-质量平衡；某些设定下成本降低 >2× 且不损质量；路由器在换强/弱模型时仍可迁移。评估用的是通用对话/偏好基准，不是 SWE/WebArena 等长程 agent 任务集。
- **url**: https://arxiv.org/abs/2406.18665
- **source_type**: primary paper
- **published**: 2024-06 (v1), 2025-02 (v4)
- **confidence**: high
- **notes**: **推断**: “把 RouteLLM 式 router 搬到 SWE-bench Verified / Terminal-Bench / τ-bench，用任务级成功 + token/费用作目标”是清晰研究缺口；公开基准侧基础设施已基本齐备（harness + 成功判据），缺的是统一成本标签与跨基准长程轨迹。

### [12] 实验可行性综合判断：SWE 系最适合做主实验；Web/OS/τ 适合次级验证；混杂必须在设计中控制
- **claim（综合）**:
  - **适合主实验**: SWE-bench Verified（成功判据硬、多 scaffold、500 题全量重放费用可控）+ SWE-Gym（训练/分析轨迹）+ SWE-Rebench 新鲜切片（防污染跟踪）+ Terminal-Bench-core（CLI 长程、~100 题）。
  - **次级**: τ-bench/τ²（状态终局 + pass^k，注意模拟器成本）、WebArena（需自建环境）、OSWorld（环境过重）。
  - **不适合当主战场**: 纯函数调用榜（BFCL 类）、GAIA 答案隐藏 split、MultiChallenge（本轮未核实）。
  - **已知混杂（有文献依据）**: ① SWE-bench 原版测试过窄/描述模糊/环境失败（OpenAI Verified 文，高置信）；② 静态公开基准污染（OpenAI 讨论 + SWE-Rebench，高置信）；③ scaffold 差异可使同一模型分数差一个数量级（OpenAI：GPT-4 Lite 2.7%→28.3%）；④ τ-bench 用户模拟器与 pass^k 随机性（原论文，高置信）；⑤ WebArena 类环境版本漂移（推断，中置信）；⑥ 公开轨迹缺成本字段（推断，高置信于“未见一等支持”的现状）。
  - **多模型重放**: SWE 系与 Terminal-Bench 通过 Docker harness + 可插拔 LLM 后端支持（高置信）；统一 token/费用/延迟需自测埋点（推断）。
- **url**: 汇总自本文件引用源
- **source_type**: synthesis
- **published**: 2026-09-15
- **confidence**: medium-high

## Dead ends

1. **WebSearch 插件不可用**：全程仅能 WebFetch 已知 URL 或 arXiv/README；arXiv API 在批量请求时出现 rate limit。
2. **Terminal-Bench arXiv ID 试错**：2507.13040 / 2504.21798 均指向无关论文；正确出处改为 GitHub README + OpenReview ICLR 2026 引用块。Terminal-Bench 2.0 / harbor 新代际任务集规模本轮未核实。
3. **MultiChallenge**：2410.18638、2410.18614 等 ID 均错配；OpenReview 被浏览器校验拦截 → 规模、评分协议、是否公开轨迹未确认。
4. **AgentGym**：2410.06504 为无关 MIMO 论文；未在本轮确认正确 arXiv/GitHub 细节 → 仅在 Dead ends 提示存在候选名，不写入 Findings 主张。
5. **mini-SWE-agent**：2501.03933 错配；未核实其日志是否含 token 字段。
6. **WebArena 812 任务数 / VisualWebArena 细节 / WebShop / ToolBench / BFCL 具体规模**：未在本轮取得一手摘要页，避免写入高置信结论。
7. **OpenHands “公开 traces 数据集”文件级 schema**：README 已转向 Agent Canvas 产品页，未定位到统一的 trajectory 发布目录 → 成本字段仍按“通常缺失”处理。

## Suggested follow-ups

1. 核实 AgentGym / AgentGym-RL 与 THUDM 仓库：轨迹是否含多环境、是否可直接做 routing 标签；mini-SWE-agent 日志 schema 是否含 tokens。
2. 用 Semantic Scholar / Google Scholar 查 “cost-aware / budget-aware LLM agent routing SWE-bench / Terminal-Bench / tau-bench” 近两年论文，确认缺口是否已被填补。
3. 在 SWE-bench Verified 上抽 50–100 题，用 2 个开源模型 + 2 个闭源 API 跑通 harness，验证自建 token/费用埋点可行性与费用上界（论文外实验）。
4. 检查 τ²-bench 官方仓库的任务生成器：能否固定随机种子，以便 pass^k 成本可预算。
5. 确认 Terminal-Bench 2.0 / harbor 数据集规模与是否引入成本指标，决定是否纳入主实验。
