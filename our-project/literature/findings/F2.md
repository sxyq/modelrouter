# F2: Agent 轨迹级 / multi-model agent 路由

## Findings

### [1] SWE-Router 在多轮 SWE agent 中用弱模型跑 K 步后读部分轨迹决定是否升级到强模型，是轨迹级路由的代表工作
- quote: "We introduce SWE-Router, a value-based temporal approach that lets a cheap model run for a few exploratory turns and reads the resulting partial trajectory before deciding whether to continue cheaply or to escalate to an expensive model."
- url: https://arxiv.org/abs/2607.00053
- source_type: primary
- published: 2026-06-29
- confidence: high

### [2] SWE-Router 明确指出仅靠 prompt 路由在 agentic SWE 上存在 Bayes-error 下界，轨迹条件化可严格优于 prompt-only
- quote: "Existing LLM routers operate on the task description alone, which inherits an information-theoretic Bayes-error floor in agentic settings… We provide a Bayes-optimality theorem showing that conditioning on the partial trajectory never harms routing and is strictly better whenever exploration is informative."
- url: https://arxiv.org/abs/2607.00053
- source_type: primary
- published: 2026-06-29
- confidence: high

### [3] SWE-Router 在 SWE-Bench Verified 上：deepseek-v3.2 为弱模型时 Route-AUC 0.780，比非时序路由基线 +15.3pp；弱模型为 gpt-5-mini 时相对最强基线 +12pp
- quote: "When deepseek-v3.2 is used as m1, SWE-Router shows Route-AUC of 0.780, which is a +15.3 pp improvement over the non-temporal routing baseline (K=0). While the router trained with gpt-5-mini's trajectories for m1 also exhibits +12 pp improvement over the strongest baseline."
- url: https://arxiv.org/html/2607.00053
- source_type: primary
- published: 2026-06-29
- confidence: high

### [4] SWE-Router Table 1 实测：更强模型 resolved 更高但总成本与每次成功成本都更高（gemini-3-pro $391.3 vs gpt-5-mini $16.6 完成 500 题），未给出「更贵模型每次成功更便宜」的实证
- quote: "SWE-Bench Verified 500 / 55.6 / $16.6  500 / 62.4 / $22.6  500 / 70.4 / $391.3  Total cost ($) 105.4 130.5 608.2"
- url: https://arxiv.org/html/2607.00053
- source_type: primary
- published: 2026-06-29
- confidence: high

### [5] SWE-Router 模型对为 weak∈{gpt-5-mini, deepseek-v3.2} vs strong=gemini-3-pro-preview，指标是 cost–vs–resolved 曲线（Route-AUC），粒度是「固定前缀 K 步后一次性 continue-or-restart」
- quote: "weak ∈ {gpt-5-mini, deepseek-v3.2}, and gemini-3-pro-preview for the strong model… SWE-Router makes one continue-or-restart decision after a fixed prefix"
- url: https://arxiv.org/html/2607.00053
- source_type: primary
- published: 2026-06-29
- confidence: high

### [6] TACIT-Switch 研究 agent 何时把控制权从便宜模型永久交给更强模型，对比 task-level、step-level、fixed-prefix 路由基线，在 comparable cost 下提升 7.4–11.1pp 成功率
- quote: "TACIT-SWITCH improves success by 7.4-11.1 percentage points over task-level, step-level, and fixed-prefix routing baselines at comparable cost… ALFWorld (48.5% with 4B Cheap; 45.5% with 9B Cheap) and DABench (73.1%)."
- url: https://arxiv.org/abs/2608.27911
- source_type: primary
- published: 2026-08-28 (v2 2026-09-04)
- confidence: high

### [7] TACIT-Switch 的优化目标是任务级期望成功率在推理预算约束下最大化，显式预测 handoff 时点而非逐步模型选择；部署时不需 teacher
- quote: "max_h E[Y_i(h)] s.t. E[Cost_i(h)] ≤ C_max… The resulting mixture-cure threshold model estimates the probability that the paired Strong rollout succeeds and, conditional on success, the handoff threshold; no teacher is required at deployment."
- url: https://arxiv.org/html/2608.27911v2
- source_type: primary
- published: 2026-08-28
- confidence: high

### [8] EvoRoute 在 GAIA/BrowseComp+ 等 agentic 基准上按子任务步动态选 Pareto 最优 LLM backbone，宣称保持/提升性能同时降本至多 80%、降延迟 >70%
- quote: "EvoRoute dynamically selects Pareto-optimal LLM backbones at each step… reduces execution cost by up to 80% and latency by over 70%."
- url: https://arxiv.org/abs/2601.02695
- source_type: primary
- published: 2026-01-06
- confidence: high

### [9] EvoRoute 路由粒度为 workflow 内显式子任务/每步；输入是 query+历史经验检索，不预测任务总成本或成功概率，而是维护 cost/efficiency/performance Pareto 前沿并自进化策略
- quote: "EvoRoute operates at the granularity of individual sub-tasks within a complex workflow. Before executing each step, it dynamically selects… retrieval… filtration… selection"
- url: https://arxiv.org/html/2601.02695v1
- source_type: primary
- published: 2026-01-06
- confidence: high

### [10] InfraMind 把基础设施状态纳入 multi-agent 编排：planner 选 topology/roles，executor 每步按 queue/cache/latency 决定调用哪个模型与推理深度，预算感知调度器重排队列
- quote: "An infra-aware executor then observes per-model queue depths, cache utilization, and response latencies at each agent step to decide which model to call and how deeply to reason; a budget-aware scheduler further reorders each model's queue"
- url: https://arxiv.org/abs/2606.11440
- source_type: primary
- published: 2026-06-09
- confidence: high

### [11] InfraMind 在低负载下相对 prior baseline 最高 +7.6pp 准确率且延迟最多降 7×，高负载下 SLO 达标率最高 99.9%（baseline 均 <50%）；模型池为 5 个开源小模型（DeepSeek-R1-Distill-Qwen-32B 等），非前沿商业模型对
- quote: "Across five benchmarks, INFRAMIND delivers up to +7.6 pp accuracy over the prior baseline at low load with up to 7x lower latency, and sustains up to 99.9% SLO compliance under high load… DeepSeek-R1-Distill-Qwen-32B, Mistral-Small-24B, Qwen2.5-Coder-14B, Llama-3.1-8B and Llama-3.2-3B"
- url: https://arxiv.org/abs/2606.11440
- source_type: primary
- published: 2026-06-09
- confidence: high

### [12] Gated-Memory Routing（EMNLP 2026 Main）每步从 query+学习到的 execution memory 中选 next role 与 backbone，Adaptive Halting Controller 可提前停；五基准最佳均值准确率超最强 baseline +2.44 点，HumanEval 推理成本降 31.9%
- quote: "At each step, the system selects the next role and backbone from this memory, while an Adaptive Halting Controller stops execution… exceeding the strongest baseline by 2.44 points, while reducing HumanEval inference cost by 31.9%"
- url: https://arxiv.org/abs/2609.00237
- source_type: primary
- published: 2026-08-31 (v2 2026-09-09)
- confidence: high

### [13] ProgRouter（EMNLP 2026 Findings）针对 multi-agent workflow 的逐步在线路由：批评 cascade/query-level 一次性决策无法适应演化状态；用 progress scorer + predictor + meta-gate 在 time/cost budget 下选 agent
- quote: "Existing cascade routing methods make one-shot, query-level decisions… ProgRouter makes online step-wise routing decisions that balance progress gain, task time budgets, and long-term operating cost efficiency."
- url: https://arxiv.org/abs/2608.25992
- source_type: primary
- published: 2026-08-26
- confidence: high

### [14] AgentOpt 把 multi-step pipeline 的 model-to-role assignment 形式化为 black-box 优化：在 matched accuracy 下最优与最差模型组合成本差 13–32×（BFCL 上 Qwen3-Next-80B 达到 Claude Opus-4.6 精度同时成本降 32×）；UCB-E 相对 brute-force 省 62–76% 评估预算
- quote: "at matched accuracy, the cost gap between the best and worst model combinations can reach 13–32×… Qwen3 Next 80B matches Claude Opus 4.6 in accuracy while reducing cost by 32×… UCB-E recovers near-optimal accuracy while reducing evaluation budget by 62-76%"
- url: https://arxiv.org/abs/2604.06296
- source_type: primary
- published: 2026-04-07
- confidence: high

### [15] AgentOpt 的路由粒度是静态/离线的角色-模型赋值（给定 pipeline + 小评估集搜索一次），不是运行时逐步切换；作者把 adaptive routing 明确标为 next stage，未做任务总成本预测或动态 escalation
- quote: "the package is intended as a foundation for a wider class of client-side optimizations beyond static model assignment, including adaptive routing, tool selection, scheduling…"
- url: https://arxiv.org/html/2604.06296v2
- source_type: primary
- published: 2026-04-07
- confidence: high

### [16] NOMA（vision paper）把 multi-agent data pipeline 建模为 query optimization：需联合优化 topology+model+engine，控制实验显示 10-agent 管线上 153× 成本、5× 延迟、25% 质量方差；Pareto 前沿从 $0.01/0.77 质量到 $1.84/0.95 质量
- quote: "a real-world 10-agent pipeline reveals extreme variance (153× cost, 5× latency, 25% quality)… 266 Pareto-optimal plans… cheapest plan at $0.01 (42.5 s latency, 0.77 quality) to a highest-quality plan at $1.84 (125.9 s, 0.95 quality)"
- url: https://arxiv.org/abs/2512.11001
- source_type: primary
- published: 2025-12-10 (v2 2026-07-07)
- confidence: high

### [17] NOMA 强调分布化成本估计（conformal prediction 等）因 agent 随机性与上游 model choice 的非加性质量传播，点估计无法支撑下游成本推理——这是任务级成本预测的开放问题而非已解方案
- quote: "estimates are essential because agents are stochastic and quality propagates non-additively: a point estimate cannot capture the uncertainty introduced by upstream model choices"
- url: https://arxiv.org/html/2512.11001v2
- source_type: primary
- published: 2025-12-10
- confidence: high

### [18] MasRouter（2025）定义 MASR：collaboration mode + role allocation + LLM routing 级联控制器；HumanEval 上降本至多 52.07%，MBPP 上超 SOTA 1.8–8.2%——是 query 级（非逐步）任务自适应路由
- quote: "MasRouter employs collaboration mode determination, role allocation, and LLM routing through a cascaded controller network… reducing overhead by up to 52.07% compared to SOTA methods on HumanEval"
- url: https://arxiv.org/abs/2502.11133
- source_type: primary
- published: 2025-02-16
- confidence: high

### [19] AgentRouter（QA 场景）用知识图 GNN 在 agents 上产生 task-aware 路由分布，论文写明 larger models are not always superior，但优化目标是 soft 聚合后的 QA 质量而非显式任务总成本；摘要承认 prior work 常偏 cost efficiency 而忽略 QA 结构
- quote: "Prior studies show that different agents and backbones exhibit complementary strengths, and that larger models are not always superior… Existing approaches to agent routing, however, often emphasize cost efficiency while overlooking the fine-grained contextual and relational structure inherent in QA tasks."
- url: https://arxiv.org/abs/2510.05445
- source_type: primary
- published: 2025-10-06
- confidence: high

### [20] MASS（ICLR 2026）与 EvoMAS（ICML 2026）是设计期 MAS 优化/生成（prompt+topology 搜索 / 进化配置生成），不是运行时按任务预测成功率或 token 的模型路由；MASS 优化 prompts/topologies，EvoMAS 在配置空间进化并报 SWE-Bench-Verified 79.1%（Claude-4.5-Sonnet）
- quote: "we propose Multi-Agent System Search (MASS), a MAS optimization framework… block-level prompt optimization; workflow topology optimization; workflow-level prompt optimization" / "EvoMAS formulates MAS generation as structured configuration generation… reaches 79.1% on SWE-Bench-Verified"
- url: https://arxiv.org/abs/2502.02533
- source_type: primary
- published: 2025-02-04 (MASS v2 2026-01-31)
- confidence: high

### [21] RouteGuard 证明路由 AUC 与 advisor 互补性不足以保证可部署增益：增益 G=πΔE 由 conditional-regret functional Φ 支配；RouterBench 上 prompt-level 可认证超 GPT-4、workload-cluster 重采样则拒绝认证；OpenRCA 三 Gemini advisor 统计冗余，协议正确拒绝认证
- quote: "Routing gain decomposes as G = πΔE, and the achievable gain is governed by a conditional-regret functional Φ, not by AUC… On OpenRCA (three Gemini advisors) the advisors are statistically redundant"
- url: https://arxiv.org/abs/2608.07583
- source_type: primary
- published: 2026-08-05
- confidence: high

### [22] TACIT-Switch 相关工作把已有方法分层：RouteLLM=生成前 request-level；FrugalGPT=learned cascade；ReDAct/TRIM=step-local 非永久干预；SWE-Router=固定前缀后一次 continue-or-restart；EvoRoute=跨显式 workflow 子任务重复选模型；本文=自适应时点的一次性永久 handoff
- quote: "RouteLLM chooses a model before generation, whereas FrugalGPT uses a learned cascade… SWE-Router makes one continue-or-restart decision after a fixed prefix… EvoRoute instead repeatedly selects models across explicit workflow subtasks… adaptively timed, one-way transfer for the remainder of the episode"
- url: https://arxiv.org/html/2608.27911v2
- source_type: primary
- published: 2026-08-28
- confidence: high
