# F7: 最近邻竞品深挖

## Findings

### [1] TRACE-Router：任务级 bandit 是真的——入队时 contextual UCB 一次性选后端并 pin 整条 trace，延迟奖励是 accuracy–latency 标量化，不是事前预测 (成功概率, 调用数, token, $)
- quote: "TRACE-Router assigns each task to a model once at admission using a contextual bandit, pins all subsequent LLM calls to the selected backend, and updates its policy using the task's terminal reward, jointly accounting for accuracy and latency." / 形式化 reward: "r^{(α)}_{t,m} = (1−α) a_{t,m} − α · min(ℓ_{t,m}/ℓ0, 1)"；选择规则为冷启动 contextual UCB: "m_t = argmax_m [μ̂_{c_t,m} + sqrt(2 log(1/δ)/N_{c_t,m})]"。决策时只知 admission context c_t = g(x_t)（首请求前可计算的粗任务描述）与 bandit 统计；"Neither final accuracy nor total latency is available when the first routing decision is routed. The reward is therefore observed only after task completion."
- url: https://arxiv.org/abs/2607.22465 / https://arxiv.org/html/2607.22465v2
- source_type: primary（Georgia Tech / Intel / Texas A&M）
- published: 2026-07-24 (v2 2026-07-27)
- confidence: high
- 决策时已知：粗 context 分类（无 LLM 调用）、已完成任务的延迟 reward 统计、backend 池。预测内容：不预测成功概率/调用数/token/$——UCB 直接在线学标量 reward 的 arm 均值，无 ex-ante 概率或成本模型。评测指标：accuracy–latency Pareto 前沿、latency-matched random-mixture 对照。数据集：τ²-Bench（retail/telecom）、Terminal-Bench、LiveCodeBench；backend 主配对 Qwen3.5-4B/9B（TB 上 9B/27B-FP8），另扩 4 模型（+Gemma-12B、DeepSeek-R1-Distill-14B）。结果：τ² 上超 latency-matched 插值 7–8 pt；Terminal-Bench 46.8%/172s vs always-27B 39.7%/268s。局限 vs 任务级 ex-ante 路由：(a) 无 per-(model, effort) 的成功/成本预测——纯粹在线 bandit，冷启动需 |C|·k·|M| 强制探索；(b) 成本用 latency 秒数代理，无 token/$ 轴；(c) 动作空间=模型池，无 reasoning-effort 轴；(d) 每个 α 维护独立 policy state，质量约束以标量化偏好参数 α 表达而非硬约束。与本课题最近：任务级 admission 粒度 + 在线学习框架；差距：无 ex-ante 多维预测与受约束选择。

### [2] TwinRouterBench：双轨步级基准——静态轨 970 条 execution-verified 前缀→tier 标签（RowPass/RowExact/TrajPass/CostSave 确定性算术），动态轨 SWE-bench Verified 真跑记 realized API spend；目标是最便宜保留步级正确的 tier，不是整任务事前成本预测
- quote: "The static track provides 970 router-visible prefixes from 520 instances across SWE-bench, BFCL, mtRAG, QMSum, and PinchBench, each paired with an execution-verified target tier estimated under a released downgrade-and-cascade protocol; scoring is deterministic arithmetic over tier labels, trajectory membership, and token costs, with no online evaluator-side LLM judge." / 理想目标: "t_i^* = min{t ∈ 𝒯 : ∃m ∈ ℳ_t such that V_i(m; x_i)=1}"，并自陈 "t_i^* is a conditional per-call quantity, not a globally optimal joint policy over the full trajectory." / CostSave 计费为 failure-aware：失败轨迹 "charge −Σ cost(t̃_i; i) at trajectory level"。

- published: 2026-05-14 (v2 2026-05-22)

- 决策时已知：router-visible 完整前缀（历史/tool 输出/检索/代码 diff）；动态轨另知 cache state、可用模型、budget。预测内容：分类到 4 档 tier（low/mid/mid_high/high），不预测 token 数/$/调用次数；token 成本只用于事后打分。评测指标：RowPass、RowExact、TrajPass、CostSave（failure-aware，variant E）；动态轨官方 resolve rate + realized spend + leaderboard bill（统一 unresolved 罚金）。数据集：静态 970 行/520 实例（SWE-bench 336 行、BFCL 248、mtRAG、QMSum、PinchBench 48）+ 动态 100 例 held-out SWE-bench Verified。被评 router：SR-KNN、ClawRouter、UncommonRoute、Opus-4.6-as-router（诊断）、训练于静态标签的 logistic。关键结果：Opus-as-router 失败——147 条 verified-high SWE 步里只预测对 7 条；一步漏档即整条轨迹失败（UncommonRoute 39/40 轨迹失败）。局限 vs 任务级 ex-ante 路由：标签是逐步执行回放得到的条件最优 tier，非事前预测；无 (model×effort) 联合空间；不学习"预计总调用数/总 token/总 $"。对本课题价值：提供现成的步级标签构造协议与 failure-aware 成本核算公式，可直接借鉴为对照协议，不构成方法冲突。

### [3] EarlyEval：中期预测+早停是评估侧减支，不是路由——LightGBM 成败双分类器对前缀打分过阈值即停；防泄漏用 leave-one-agent-out + 按任务划分 + Platt 校准
- quote: "EarlyEval, a lightweight framework that trains a pair of LightGBM success and failure classifiers over behavioral, textual, and reference-solution features, and halts an agent run the moment either classifier crosses a calibrated confidence threshold" / 防泄漏: "we adopt a leave-one-agent-out protocol that holds out one agent at a time and trains only on the remaining ones"；训练划分 "partition the trajectory pool by task into a training fold and a held-out validation fold; all prefixes originating from a given trajectory are strictly restricted to the same side of the split"；前缀按 1/(T+1) 加权防长轨迹主导；校准 "p = σ(a·logit(ŝ)+b)" 在验证折上做 Platt scaling。

- source_type: primary（SJTU/SMU/ECNU；代码 github.com/inphotoo/earlyeval）
- published: 2026-09-02
- confidence: high

### [4] SWE-Router：成本目标是 r̂_i(q)−λc_i 标量化（c_i 视为 q 无关常数），选择发生在 K 步探索之后而非事前；价值头只预测弱模型成功率，不预测 token/$
- quote: 路由规则: "Invoke m1 if r̂1(q)−λc1 > r̂2(q)−λc2, m2 otherwise, where r̂i(q)∈[0,1] is the estimated probability mi resolves qi, ci>0 is its expected inference cost (USD; on long agentic trajectories cost is model-dominated, so we treat ci as q-independent)." / 实际部署用 one-sided 简化: "continue iff r̂1 ≥ λ′′"，其中 r̂1 由 Qwen2.5-Coder-7B + LoRA 分类头在 m1 的 K 步部分轨迹上给出；"The K weak-model turns are paid up-front and counted in any escalated run's cost"；升级时 m2 从 q 重启。Bayes 最优定理："V(S_t) ≥ V(Q)"（部分轨迹条件化不劣于纯 prompt）。
- url: https://arxiv.org/abs/2607.00053 / https://arxiv.org/html/2607.00053v1
- source_type: primary（UCL 等；ICML 2026 DLC Workshop）
- published: 2026-06-30
- confidence: high
- 决策时已知：K 步 m1 探索后的部分轨迹 𝒯_{≤K,1}（决策时点在任务开始后 K 步）；价值头参数。预测内容：只预测弱模型 P(resolve)；c_i 是池级常数（USD），不逐任务预测 token/调用数/总账单——成本差异被折进 λ 或 λ′′ 一个标量阈值。评测指标：AUROC、Route-AUC（cost-vs-resolved 归一化曲线下面积，0=随机/插值、1=all-strong@all-strong 质量 at all-weak 成本）；SB-V test 上 deepseek-v3.2→gemini-3-pro Route-AUC 0.780（比 K=0 基线 +15.3pp）。数据集：SWE-Smith（train/val/test，仓库不相交）+ SWE-bench Verified（mix-1 中 4/5 折入训练，held-out 100 例）；模型对 (gpt-5-mini|deepseek-v3.2 → gemini-3-pro-preview)，mini-SWE-agent 75 步预算；发布多模型轨迹数据集。局限 vs 任务级 ex-ante 路由：(a) 非事前——需要先付 K 步探索成本；(b) c_i 不随任务变化，无调用数/token 预测；(c) 只有 weak/strong 二元对，无 effort 档位；(d) 固定前缀 K，非自适应停止。与本课题最近：形式化 r̂−λc 效用与 Route-AUC 评测；差距：ex-ante 维度（k=0 时论文自己的 K=0 基线恰好最弱）正是本课题要补的。

### [5] TACIT-Switch：约束方向与本课题相反——max 成功 s.t. 成本预算（非 min 成本 s.t. 质量下限），且 handoff 在线发生；但其 (π_γ·F_β,s) 双分量分解可借来建模"可救概率×进度"
- quote: 优化问题: "max_h E[Y_i(h)] s.t. E[Cost_i(h)] ≤ C_max." / 部署分数: "q̂_i(t) = π̂_i F_{β̂,ŝ}(R_i(t) | x_i)"，其中 π_i = P(B_i=1|x_i) 是 paired-Strong 成功概率（logistic incidence），F 是条件阈值 CDF（log-normal AFT，区间删失），R_i(t) 为非负诊断量的累积风险；"permanently hands control to π_s when q̂_i(t) ≥ α"；阈值 α 在开发集上按预算选定后固定。"TACIT-Switch does not require a particular cost model. It first estimates the handoff score q̂_i(t); the application-specific cost enters only when choosing its decision threshold α on development data."
- url: https://arxiv.org/abs/2608.27911 / https://arxiv.org/html/2608.27911v2
- source_type: primary（北师大/港理工）
- published: 2026-08-28 (v2 2026-09-04)
- confidence: high
- 决策时已知：Cheap 已执行轨迹的逐步诊断 u_i(t)（重复动作、不确定性 NLL、无效生成、停滞等）+ 任务特征 x_i；TACIT 监督来自离线 teacher 标注的删失 handoff 窗口（仅 AB=01 有标注）。预测内容：预测 Strong 可救概率 π 与阈值分布 F——是成功预测器，不是调用数/token/$ 预测器；成本以预算约束+事后 realized call 计数出现。评测指标：held-out success @ 开发选定的 cost cap；干预率、Strong share。数据集：机制仿真（10 步 3 状态）、ALFWorld（4B/9B Cheap vs 27B Strong；scale-up Test274 上 TACIT 151/274=55.1% @176.9 units vs Task Router 41.2% @184.7）、DABench（73.1%）。结果：比 task-level/step-level/fixed-prefix 基线 +7.4–11.1pp（同成本）。局限 vs 任务级 ex-ante 路由：(a) handoff 在线/自适应时点，非 admission 一次性；(b) 约束是"成功在预算下"，与"成本在质量约束下最小"对偶但不可直接替换；(c) 成本模型显式留给应用；(d) 无 effort 轴、无 token 预测；(e) 需要 teacher 删失标注。对本课题价值：mixture-cure 式分解（可救概率 × 条件进度）+ 区间删失是处理"成功与进度双重不确定性"的可借形式；其 Task Router 基线恰是本课题设定的最弱版本（task-level、无预测）。

### [6] UniScale：动作空间最接近 (模型×推理档位)——UIS = (M, QP, CP, BS) 联合配置，LinUCB 在线选，成本用 eFLOPs 解析模型；但是单请求 QA 推理，非长程 agent 任务，且无 ex-ante 多目标预测
- quote: "We define Unified Inference Scaling (UIS) as a single unified inference-time decision space. We parameterize each inference execution through a joint configuration (M, QP, CP, BS)." / "each a∈𝒜 corresponds to a specific UIS configuration (M, QP, CP, BS)"；目标为 regret: "R_T = E[Σ_t (r(q_t, a*_t) − r(q_t, a_t))]"，a_t 由 LinUCB 选: "a_t = argmax_a (x_{t,a}^T θ̂_t + α sqrt(x_{t,a}^T A_t^{-1} x_{t,a}))"；reward "is a convex combination of quality and cost"（Quality-Priority / Cost-Sensitive 两种模式）；成本 "UIS Cost Model utilizes equivalent FLOPs (eFLOPs) to map computational and memory overhead into a unified metric"，含 prefill/decode/verify 三项解析分解（Prop D.13–Remark D.16: C_UIS = C_prefill + Σ_j[C_inc^{(j)} + C_ver^{(j)}]）。
- url: https://arxiv.org/abs/2605.30898 / https://arxiv.org/html/2605.30898v1
- source_type: primary（ICML 2026 接收）
- published: 2026-05-29
- confidence: high
- 决策时已知：查询语义 embedding s_q（Transformer 编码器）+ 动作语义描述 s_a（模型参数量、GPQA/AIME/LCB 等锚点分）+ 历史 (x,a,r)。预测内容：线性 reward 估计（质量与 eFLOPs 的标量组合），不显式分解预测调用数/token/$，也不预测 P(success)。评测指标：cumulative regret、accuracy–cost Pareto、Cost-Sensitive vs Quality-Priority 双模式 reward。数据集：AIME'24+'25 + MATH-500 共 210 题（50 warm-up + 160 policy 迭代）；模型池 Qwen3 0.6B–32B；verifier Skywork PRM 1.5B/7B；泛化实验扩到非数学任务（成本 −59.97%，acc −0.63pp）。关键消融：UIS 全空间 vs BEST-Route* 子空间——Cost-Sensitive 下全空间 acc +14.37pp 且算力仅 ~10%。局限 vs 任务级 ex-ante 路由：(a) 单发 QA/推理题，非多步 agent 轨迹（无调用次数随机性）；(b) eFLOPs 非美元；(c) 在线 bandit 适应漂移，非事前 per-task 预测+选择；(d) effort 轴=TTS 搜索参数（QP/CP/BS），非模型原生 reasoning-effort 枚举，但概念上可对齐。对本课题价值：(model, effort) 联合动作空间 + 语义动作表示 + eFLOPs 成本模型三件套可直接映射到 (model × reasoning-effort) 的事前成本解析；差距在于把 bandit 换成事前预测器即可构成相邻系统，仍无"质量约束"形式。

### [7] RouteGuard：认证协议——G = π·Δ_E 精确分解、上界 Φ = E[max_j η_j(T) − η_1(T)] 由 gating 信号的 informativeness 决定（非 AUC）；对本课题的含义是"部署前先证明路由有增益"，而非逐任务选配置
- quote: "Routing gain decomposes as G = π Δ_E, and the achievable gain is governed by a conditional-regret functional Φ, not by AUC." / "max_R G(R) = Φ = E[max_j η_j(T) − η_1(T)], attained by the Bayes selector (Theorem 1)"；"the protocol certifies a gain over GPT-4 under prompt-level sampling and withholds it under workload-cluster resampling, because the gain rests on 3 of 86 workload cells"；OpenRCA 上 "advisors are statistically redundant… the realized oracle sits at or below the independence baseline"（独立性参考线），协议拒绝认证。有限样本 bracket: Bernstein B(m,δ) + Le Cam 下界（fixed-activity 类上 minimax 常数 c*=2π 锐）；robustness 相变 ρ* = πΔ_E/2。自限范围: "We scope to accuracy-only, where the AUC-vs-Φ phenomenon is cleanest, and cost-aware extensions compose with the same bracket."

- source_type: primary（Miami→Google；stat.ML）
- published: 2026-08-05

### [10] 补充检索：ZIP-RC 用同一前向的保留 logits 联合预测 reward 与剩余长度（cost proxy）——概念上最接近"同时预测成功与成本"，但粒度是单模型 TTS token 级，无跨模型路由、无 agent 任务

This full joint distribution is used to compute a sampling utility which is the linear combination of the expected maximum reward, total compute, and latency of set of samples if generated to completion."
