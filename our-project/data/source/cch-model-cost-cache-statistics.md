## 3. 字段含义确认

后台常见列（调用次数、输入、缓存读取、缓存写入、输出、单次成本、成功率、失败数）必须按原始单次字段重新确认，不能把页面展示值直接当成总量或估计值。

### 3.1 调用结果

| 报告字段 | 定义 | 类别 | 公式 |
|---|---|---|---|
| 数据记录数 / 总调用次数 | 过滤后 message_request 行数 | **总量** | COUNT(*) |
| 成功次数 | success_rate_outcome='success' | **总量** | 后台成功率函数 |
| 失败次数 | success_rate_outcome='failure' | **总量** | 后台成功率函数 |
| 排除次数 | success_rate_outcome='excluded' | **总量** | 404、部分499、限流/配额等 |
| 未终结次数 | success_rate_outcome IS NULL | **总量** | 未 finalized |
| 成功率（后台口径） | 只在 countable 集合 | **比率，非页面估计** | 成功/(成功+失败) |
| 失败率（后台口径） | 同上 | **比率** | 失败/(成功+失败) |
| 成功率（相对全部调用） | 含 excluded/unfinalized | **比率** | 成功/总调用 |
| is_success 成功次数 | ledger 布尔口径 | **总量** | error 空且 status 空或 <400 |

后台成功率不是简单的 status_code<400。`fn_compute_message_request_success_rate_outcome` 会把 404、部分 499、quota/rate limit、resource_not_found、client_abort（除 no_first_byte）标成 excluded，不进入成功率分母。

### 3.2 Token

| 报告字段 | 原始列 | 类别 | 公式 |
|---|---|---|---|
| 普通输入 token 总量 | input_tokens | **总量** | SUM(COALESCE(input_tokens,0)) |
| 缓存读取 token 总量 | cache_read_input_tokens | **总量** | SUM(COALESCE(cache_read_input_tokens,0)) |
| 缓存写入 token 总量 | cache_creation_input_tokens | **总量** | SUM(COALESCE(cache_creation_input_tokens,0)) |
| 输出 token 总量 | output_tokens | **总量** | SUM(COALESCE(output_tokens,0)) |
| Token 总量 | 四项相加 | **总量** | 输入侧三项 + 输出 |
| 平均每次 * | 同上 | **单次平均值** | 总量/总调用次数，NULL 当 0 |
| P50/P90 * | 同上 | **百分位，不是均值** | percentile_cont，NULL 当 0 |

Codex/OpenAI-compatible 入库前会把 cache read/write 从 input_tokens 拆出。Anthropic 按上游 usage 原样写入。因此「普通输入」一般不含缓存桶。

### 3.3 成本

| 报告字段 | 来源 | 类别 | 公式 |
|---|---|---|---|
| 总成本 | cost_usd | **总量** | SUM(COALESCE(cost_usd,0)) |
| 平均单次调用成本 | cost_usd | **单次平均值** | 总成本/总调用次数 |
| 成功调用的平均成本 | cost_usd | **条件平均值** | AVG FILTER (后台成功) |
| 失败调用的平均成本 | cost_usd | **条件平均值** | AVG FILTER (后台失败) |
| 成本中普通输入部分 base | cost_breakdown.input | **总量，乘倍率前** | SUM(input) |
| 成本中缓存读取部分 base | cost_breakdown.cache_read | **总量，乘倍率前** | SUM(cache_read) |
| 成本中缓存写入部分 base | cost_breakdown.cache_creation | **总量，乘倍率前** | SUM(cache_creation) |
| 成本中输出部分 base | cost_breakdown.output | **总量，乘倍率前** | SUM(output) |
| 成本中 * 部分 billed | base×multipliers | **总量，与 cost_usd 同口径** | base*provider_multiplier*group_multiplier |
| 单次成本 P50/P90 | cost_usd | **百分位，不是均值** | percentile_cont |

`cost_breakdown` 键：input, output, cache_creation, cache_creation_5m, cache_creation_1h, cache_read, base_total, provider_multiplier, group_multiplier, total。input/output/cache_* 是 base 成本；total 与 cost_usd 是乘过倍率后的账单总成本。无 breakdown 的行，分项记空，不把 cost_usd 硬拆。系统设置 billNonSuccessfulRequests 默认 false；billHedgeLosers 默认 true。

### 3.4 缓存命中率

| 报告字段 | 类别 | 公式 |
|---|---|---|
| 缓存命中率 token 加权 | **总量加权，不是页面估计** | SUM(cache_read)/SUM(input+cache_read+cache_write) |
| 缓存命中率 请求平均 | **请求平均** | 仅分母>0 的请求再平均 |

这是 token 份额，不是缓存次数命中率。

### 3.5 推理档位

从 special_settings 按优先级取 effort：1) codex_reasoning_effort 2) openai_reasoning_effort 3) anthropic_effort。取不到记 `(unspecified)`。观测档位：none, minimal, low, medium, high, xhigh, max。`(unspecified)` 只表示该次没有写入 effort 事件。

### 3.6 供应商与系列

- 供应商：model_prices.price_data.vendor；缺失则按模型名前缀推断。
- 模型系列：优先 price_data.model_family，因此会出现 gpt-sol / gpt-terra / gpt-luna。
- 上游/中转账号品牌名称已全部剔除，不作为统计维度。
