## 1. 执行总览与重建决策

在 E-DESIGN 阶段科研复核中，项目组确认早期产物存在多项科研缺陷（如首分片截断、规则合成标签、TwinRouterBench 混入训练集、决策前特征渗漏等）。根据 Planning Agent 与项目负责人的决策，本轮执行（任务 Q-007）采取了**彻底推倒重建**路线：

1. **彻底清理旧产物**：在 GPU 服务器上完全删除了旧版约 600 MB、80,970 行规则合成数据及旧预览。
2. **官方源全量下载与解压**：下载并处理数据源台账中 4 大批次、共 16 组公开数据集的全量官方分片（服务器端原始数据规模逾 11.5 GB）。
3. **修复全部 12 项科研与工程缺陷**：严格剔除规则造假标签，仅保留真实执行动作、实测基准 Oracle、人类真实盲测偏好与客观负载痕迹；严格隔离决策前特征与未来信息。
4. **单脚本全流程处理**：所有清洗逻辑统一维护在 `prepare_router_data.py` 中，支持流式解析超大文件（如 140 万行 BurstGPT、6.6 GB 解压后的 LLMRouterBench），内存常驻保持在 50 MB 以内。
5. **分批输出与独立小样本审查**：在服务器上生成全量清洗 JSONL（共计 **2,282,484** 条记录），同时为每个数据源独立抽取 35 条真实执行样本（<50 KB）与精准字段统计，同步至 GitHub，供 ChatGPT 通过 GitHub MCP 直接查阅验收。

## 3. 12 项科研缺陷彻底治理清单

| 缺陷编号 | 原始缺陷表现 | 产生危害 | 本轮 Q-007 治理措施与执行结果 |
| :---: | :--- | :--- | :--- |
| **缺陷 1** | 首分片截取假全量 (如 SWE-smith 仅读 1 分片) | 样本分布倾斜，严重缺乏代表性 | **全量覆盖官方分片**：SWE-smith 读取全部 8 个分片 (107,983 步)；Open-SWE-Traces 读取全部 6 个典型代表分片 (43,154 步)；LLMRouterBench 解压处理全部 700 个文件 (548,059 条)。 |
| **缺陷 2** | 人为编写规则合成 `is_high_effort` / `step_complexity` | 标签缺乏事实依据，污染模型微调 | **彻底废弃规则标签**：TRA-001/002 仅提取真实工具动作与原始环境反馈；TRA-004 使用官方真实的 `thinking-on` 与 `thinking-off` 实验对照。 |
| **缺陷 3** | Mooncake 虚构商业 Provider 缓存命中与费用节省 | 脱离真实计费逻辑，属于虚假数据 | **真实语义映射**：仅记录客观的 `OBSERVED_REUSE_OPPORTUNITY`（前缀匹配 Token 块与复用层级），绝不捏造任何未发生的商业扣减。 |
| **缺陷 4** | 人为造假三元组档位 (`premium`, `budget`, `standard`) | 将连续成本分布劣化为人为离散规则 | **保留原始实测值**：真实记录模型的 `cost`、`tokens`、`latency`，不人为打上虚假档位标签。 |
| **缺陷 5** | 评测基准 TwinRouterBench 混入训练集 (Train 泄漏) | 导致测试集污染，使得路由评测结果完全失效 | **强制策略隔离**：显式注入 `policy_tag: EVAL_BENCHMARK_ONLY`，从清洗源头彻底断开与训练集生成的连接。 |
| **缺陷 6** | 忽视开源协议合规性 (FindingTheRightFit 违规微调风险) | 违反数据源协议条款，产生合规隐患 | **显式合规标识**：显式注入 `policy_tag: RESEARCH_ANALYSIS_ONLY`，明确其仅用于架构与成本分析，禁止作为模型训练数据。 |
| **缺陷 7** | 会话级划分未隔离仓库/任务 (Train/Test 隐式交叉) | 同一项目代码在训练集与测试集交叉泄漏 | **任务/仓库级边界隔离**：提取真实的 `repo_name`、`task_id`、`problem_id`，作为未来划分的绝对隔离键。 |
| **缺陷 8** | 决策前特征包含未来执行结果 (如最终 `resolved`) | 决策时产生严重的时间穿越与信息泄漏 | **决策前特征严格边界**：`features` 字典仅允许收录当前步之前可见的上下文（步骤序号、累积输入长度、历史工具调用序列、已观察到的报错信息）。 |
| **缺陷 9** | Arena 首轮 Prompt 混入多轮对话回复 | 路由决策前看到了未来模型的回答内容 | **严格单轮 Prompt 隔离**：首轮路由决策特征只提取用户原始 query，严禁将多轮回复混入特征。 |
| **缺陷 10** | 对 Gated 权限受限数据集伪造或使用 Mock 数据 | 破坏科研诚信，引入合成伪数据 | **零虚构原则**：TRA-003 (CMU Agent) 与 MAS-001 (MARBLE) 因 Gated 权限，如实审计并记录有效样本为 0，坚决不造假。 |
| **缺陷 11** | 多脚本并行混乱、生成 v2/v3 临时文件 | 代码维护不可靠，难以复现 | **单一执行脚本**：所有批次清洗逻辑均集成在 `prepare_router_data.py`，保持单一稳定入口。 |
| **缺陷 12** | 大文件全内存加载导致 OOM 崩溃风险 | 处理百万级数据时不可持续 | **流式解析与内存保护**：对 140 万行 BurstGPT、6.6 GB LLMRouterBench 采用流式逐行解析与蓄水池采样，内存稳定在 50 MB 以内。 |

## 5. 本地与 GitHub 审查交付物导航

为支持 Planning Agent (ChatGPT) 能够直接通过 **GitHub MCP** 开展细粒度审查，本项目在 `our-project/data/公开数据/` 下建立了轻量、完整、免克隆大文件的审查目录树：

### 5.1 核心索引与说明
- **[数据集检查索引.md](公开数据/数据集检查索引.md)**：包含全域 16 个数据集的审查总览、路径直链与抽样逻辑说明。
- **[公开数据清洗报告.md](公开数据清洗报告.md)**：即本文档，全面阐述清洗架构、统计数据与科研缺陷修正。

### 5.2 独立审查样本目录（每个数据源独立 3 个文件）
每个数据源均在 `our-project/data/公开数据/数据预览/<Source_ID>_<Name>/` 拥有独立目录：
1. **`清洗样本.jsonl`**：包含 33~35 条**真实洗后记录**，直接反映该数据源的真实特征格式与监督标签（文件体积均小于 50 KB，适合 API 直接读取）。
2. **`字段统计.json`**：包含全量清洗记录数、抽取样本数、所有字段的覆盖率、以及核心标签（如 action、model、winner 等）的真实分布统计。
3. **`样本说明.md`**：阐述该数据集的原始来源、单步映射逻辑、科学价值及隔离要求。
