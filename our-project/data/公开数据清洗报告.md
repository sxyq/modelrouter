## 0. Planning 审查纠偏与实测总量对齐结论

在 2026-10-09 Planning Agent（ChatGPT）对 GitHub 提交的代码、样本及统计开展独立科研审查后，指出了一系列事实不符、下载覆盖缺漏与代码级时序泄漏缺陷。Execution Agent 针对上述问题，在保持服务器合法已下载原始文件的前提下，进行了全面的下载补齐、代码纠正与全量重新清洗，取得如下结论：

### 0.1 数据总量彻底对齐与历史差额根因澄清
- **历史差额根因**：此前报告与索引填报的 2,282,484 条与统计 JSON 汇总的 3,963,661 条之间存在 1,681,177 差额，集中在 TRA-001、TRA-002、TRA-004。经服务器溯源排查，旧报告误将**轨迹/Episode 总数**（TRA-001 43,154、TRA-002 107,983、TRA-004 2,736）填入了表格中的“有效样本量”列，而 `字段统计.json` 统计的是**单步决策步数**（1,040,564、783,438、11,048）。
- **本轮全量扩充与精确对齐**：本轮补齐了 TRA-001 的 12 个分片、TRA-002 的全部 24 个分片（8 ticks + 8 tool + 8 xml）、TRA-004 的全部 30 个模型文件，并修复了步骤级动作抽取。经服务器全量重新清洗与物理 `wc -l` 严格核验：
  - **服务器清洗后实际有效决策记录总数**：**6,600,628** 条。
  - **16 个数据源 `字段统计.json` 汇总数**：**6,600,628** 条。
  - **二者差额**：**0**（完全吻合，彻底根除统计口径与物理文件不一致问题）。

### 0.2 十项核心科研缺陷彻底修正确认
1. **时序泄漏修正**：工具调用计数 `prior_tool_calls_count` 与累积字符数严格在当前 Assistant 决策后才递增，第一步严格保证为 0。
2. **模型标识真实性**：Open-SWE-Traces 彻底废除将 Qwen3.6/Qwen3.5 笼统标为 Qwen2.5 的映射，严格保留真实厂牌（`Qwen3.6-27B`, `Qwen3.5-122B-A10B`, `Qwen3.8-27B`, `DeepSeek-V4-Flash-0731`, `MiniMax-M2.5`）。
3. **SWE-smith 动作真实抽取**：新增 `extract_swesmith_action()` 跨 ticks、tool 与 xml 三类 split 解析真实工具调用，识别出 125.6 万次 `str_replace_editor`、90.1 万次 `bash` 与 12.2 万次 `submit`，彻底消除“全为 text_response”的严重缺陷。
4. **AgentSuite 跨模型同题对齐**：提取 `meta.id` 作为跨 30 个模型和思考模式的 273 个独特任务实例键，输出同题跨模型审查样本组。
5. **Mooncake 严格时序与 LCP 前缀匹配**：Trace 严格按 `timestamp` 升序排列，弃用无序集合交集，改用从第 0 块开始的最长连续公共前缀（LCP）匹配；`output_length` 移入 `ground_truth_outcome`；审查样本按时间连续抽取 35 个到达请求展示动态演进。
6. **TwinRouterBench 未来信息隔离**：`total_steps` 从 `pre_decision_state` 中彻底移除，仅保留在事后结果与元数据中，绝不泄漏未来总步数；保持 `EVAL_BENCHMARK_ONLY`。
7. **LongMemEval-V2 载入真实题目**：下载并解析 `questions.jsonl`，注入真实题面、领域（enterprise）、环境（workarena）、答案与评估函数，解决空干草堆缺陷。
8. **MemoryCraft 扩充多来源**：不仅读取 `longmemeval` 与 `locomo`，更完整纳入 `ama_bench.jsonl` 与 `membench.jsonl`，清洗记录扩充至 23,884 条。
9. **真实缺失率动态计算**：彻底移除硬编码 `missing_rate: 0.0`，编写 `compute_field_missingness()` 动态遍历计算所有字段的真实空值率。
10. **执行入口统一与独立批次**：在唯一脚本 `prepare_router_data.py` 中增加 `--mode public`，实现不碰触私有 Blog/CCH 数据的独立公开批次清洗。

## 2. 核心数据特征与科研监督性质说明

### 2.1 真实监督标签的四种类型
ModelRouter 坚决杜绝任何人工启发式规则（如“按文本长度或关键词强行划分高低档位”）合成的虚假路由标签。本轮清洗的所有监督标签均来源于现实世界可验证的客观事实：
1. **`OBSERVED_ACTION`（客观执行动作）**：
   - 涵盖 TRA-001（2,075,629 步）、TRA-002（2,331,584 步）、TRA-004（41,430 步）。
   - 真实记录了前沿模型（Claude 3.7 Sonnet, Qwen3.6, DeepSeek-V4, Kimi-K2 等）在面对具体软件工程或通用 Agent 任务时的单步工具调用（`str_replace_editor`, `bash`, `submit`）、推理思考长度及事后是否通过测试。
2. **`POST_HOC_BENCHMARK_ORACLE`（实测性能天花板）**：
   - 涵盖 ROUTE-001（548,059 条）、ROUTE-002（36,497 条）。
   - 真实记录各主流模型（GPT-4, Claude-3.5, LLaMA-3 等）在 AIME, SWE-bench, HumanEval 等权威基准上的实测得分、消耗 Token 与 USD 费用，以及最优 Oracle 路由选择。
3. **`HUMAN_PREFERENCE`（真实人类盲测偏好）**：
   - 涵盖 ROUTE-004（57,477 场对决）。
   - 真实记录人类众包双盲评审下的模型两两对比胜负（model_a 胜、model_b 胜、平局），直接作为路由器在质量对齐维度的监督先验。
4. **`OBSERVED_WORKLOAD` / `OBSERVED_REUSE_OPPORTUNITY`（客观负载与前缀拓扑）**：
   - 涵盖 TIME-001（1,404,294 条）、CACHE-001（39,632 条）。
   - 客观呈现微软 Azure 真实生产到达时序间隔、请求长度，以及 Mooncake FAST'25 生产会话中 512-Token 粒度真实前缀块的最长连续公共前缀（LCP）复用可能。

### 2.2 治理隔离策略严格执行
- **`TRAIN_ROUTER_CANDIDATE`**（共计 6,593,454 条）：可作为路由决策训练或偏好微调的候选数据。未来微调前，必须以 `instance_id` / `repo` 为单位进行严格的任务级 Train/Val/Test 拆分。
- **`EVAL_BENCHMARK_ONLY`**（TwinRouterBench，970 步）：作为步级模型能力降级搜索的标准评测集，从清洗源头彻底打标，**严禁混入任何训练集**。
- **`RESEARCH_ANALYSIS_ONLY`**（FindingTheRightFit，6,204 条）：因受官方协议限制禁止模型微调，严格标明仅用于多框架成本对比与系统开销参照。
- **`GATED_PENDING`**（CMU Agent, MARBLE）：实事求是记录受限准入状态，有效样本为 0，坚决不编造 Mock 数据。

## 3. GitHub 独立审查样本验证指南

ChatGPT 可直接通过 GitHub MCP 工具读取 `our-project/data/公开数据/数据预览/` 下的各个子目录开展独立复审：

1. **TRA-004 跨模型同题对照组**（`TRA-004_AgentSuite/清洗样本.jsonl`）：
   - 审查样本按相同任务实例（如 `INFERENCE_MEMORY_674552683acc221...`）连续成组排列，可直接比对 DeepSeek-R1、DeepSeek-V3、DeepSeek-V3.2 (thinking-on vs thinking-off)、Kimi-K2 等在同一道题目下的行为差异与得分。
2. **CACHE-001 动态前缀缓存序列**（`CACHE-001_Mooncake/清洗样本.jsonl`）：

4. **MEM-003 真实长程记忆题面**（`MEM-003_LongMemEval-V2/清洗样本.jsonl`）：

5. **动态非空率验证**（所有数据源的 `字段统计.json`）：
   - `fields_schema` 均由当前样本池动态统计计算生成，不再存在硬编码 `0.0`。
