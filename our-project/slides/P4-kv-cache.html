① KV Cache 原理

一次 prefill 给每层、每头、每个 token 算一对 K 和 V，留下来；Q 是临时的，用完就扔，所以叫 KV Cache。之后每生成一个 token，只算它自己那份，前面的直接读缓存。

② 多 Agent 的共享前缀

能不能复用同一份缓存，取决于三件事：前缀是否逐 token 对齐、框架是否开了前缀缓存、各 Agent 是否用同一套系统提示词和工具定义。
默认 · 独立推理

各算一遍，显存里存两份一样的

引擎给每个请求单独建一份 KV Cache。系统提示词一模一样，也各算一遍、各存一份，这是最常见的缓存浪费。

开启前缀缓存

RadixAttention：相同前缀只算一次

用一棵 Radix 树按 token 序列索引算过的 KV，新请求吃到最长匹配前缀，只有新增后缀才计算。多 Agent 高并发场景收益最大。

语义缓存 · 别混淆

它复用答案，KV 并没有共享

按语义相似度检索历史问答，命中就直接返回结果，根本不进模型。真正 KV 级的共享只有前缀缓存。
