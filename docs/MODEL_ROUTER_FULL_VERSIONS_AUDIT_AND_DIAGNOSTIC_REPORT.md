## 一、 执行摘要与审核核心结论（Executive Summary）

针对 Planning 团队重点关注的问题：
> **“为什么项目训练了这么久、迭代了这么多版本、数据量从 4.5k 扩充到 382 万，核心效果感觉不太对，没有呈现持续、单调的进步，甚至在某些指标上还出现回退？”**

经对项目历史上产生的 **133 个 Checkpoint（含保留的实体权重与修剪淘汰的评估档案）**、**4 大实验技术阶段**以及 **S1/S2/S3 三大任务交互表现**进行底层数据挖掘与第一性原理推演，审计团队得出以下 **5 大核心科研结论**：

1. **评测集天花板效应（Bayes Error Ceiling）**：  
   核心路由任务 S1 的验证集仅 **561 条样本**，本质是预测 **Chatbot Arena 匿名双模型盲测的人类偏好**。NLP 经典人评一致性（Inter-Annotator Agreement）通常在 65%~75% 之间。模型在高质量单任务（F06_S1）上取得的 **68.09% 准确率（382/561）**，在统计学上已无限逼近人评噪声下的理论贝叶斯最优上限。期望轻量模型在主观性极强的对战上突破 80%~90% 在数学和数据本质上是不现实的。
2. **多任务目标冲突与负迁移（Multi-Task Negative Transfer）**：  
   数据表明，当进行纯 S1 训练时，模型 S1 准确率可达 **68.09%**；但当引入 S2（任务执行成败，356万条）与 S3（输出长度阶梯，132万条）进行联合训练时，S1 准确率在百万级大模型（F01~F04、ALGN_02/04）中全线降至 **63.64% ~ 66.84%**。在未做梯度投影（PCGrad）或任务门控隔离的情况下，S2/S3 的梯度与 S1 发生严重拉扯，产生明显的负迁移。
3. **数据扩增带来的信噪比稀释（Data Scaling Dilution & Label Noise）**：  
   从 3 万条真实 Arena 对战扩增到 382 万全量样本的过程中，混入了大量启发式规则清洗、弱监督与跨模型伪标签数据。对于 421M 的小容量模型，海量弱标注数据带来的噪声占满了参数容量，抑制了尖锐决策超平面的形成。
4. **小样本评测集的统计方差（Evaluation Statistical Noise）**：  
   由于 S1 验证集仅 561 条，**1 条样本的得失即影响 0.178%**。66.84%（375/561）与 68.09%（382/561）之间仅仅相差 **7 个样本**。在数百样本集上的小幅度震荡往往是随机方差，而非模型能力的退化。
5. **模型并非没有进步，而是进步体现在被忽略的辅助维度（Multi-Dimensional Progression）**：  
   如果只盯着 S1 单一准确率，会产生“没有进步”的错觉；但全盘数据审查显示：  
   - **S2 任务解决率预测准确率**：从纯单任务的 45.70%（低于盲猜）跃升至 F04 的 **56.08%（+10.38%）**；
   - **S3 长度档位预测准确率**：从单任务的 28.41% 暴涨至 F02 的 **55.69% 与 F04 的 50.67%（+22%~+27%）**；
   - **全量多任务收敛 Loss**：从早期的 0.63+ 稳定平滑收敛至 **0.44~0.45**。  
   这证明模型在多任务联合感知上取得了坚实进步，但多任务优化目标与单跳 S1 偏好形成了“零和博弈”。

## 四、 核心科研归因深度剖析（Why No Monotonic Improvement?）

针对 Planning 团队的核心困惑，以下提供具备坚实理论与实证支撑的五大归因：

### 归因 1：评测集天花板与贝叶斯误差限制（Bayes Error Ceiling & Annotator Variance）
* **现状**：S1 验证集仅 **561 条样本**。任务形式为：给定 Prompt 与候选模型 A/B，预测人评投票（如 `gemini-pro-dev-api` vs `llama2-70b-steerlm-chat`）。
* **理论上限**：根据 LMSYS Chatbot Arena 的公开学术统计，人类众包标注者在面对两个相似能力的顶尖大模型时，**两两人类标注之间的一致性（Inter-Annotator Agreement, Cohen’s Kappa）通常只有 0.65 ~ 0.72**。换言之，即使是人类专家自己来盲测，同一道题也有 30% 左右的分歧！
* **实证对比**：
  $$\text{S1 最高准确率} = 68.09\% = \frac{382}{561}$$
  $$68.09\% \approx \text{人类评委共识上限 (约 68\%~70\%)}$$
* **结论**：在当前 561 条 Arena 验证集上，68% 已经触碰了该任务的**贝叶斯不可约误差界限（Irreducible Bayes Error）**。在没有更大、更具客观裁决标准（如以代码执行或数学确切答案为 Ground Truth）的新评测集之前，期望模型单调上涨到 80%~90% 是不符合数据本质的。

### 归因 2：多任务目标冲突与负迁移（Multi-Task Objective Interference）
* **机制**：
  - **S1（模型偏好路由）**：要求模型学习细粒度的文本语义质量、逻辑深度与对齐偏好；
  - **S2（任务执行成败）**：要求模型根据 Prompt 判断外部沙盒代码能否成功执行（Binary Classification）；
  - **S3（输出 Token 长度阶梯）**：要求模型预测目标模型回答的长度区间（Short/Medium/Long/Extended）。
* **梯度冲突实证**：
  - 当我们看 S2 和 S3 时，多任务训练取得了惊人的成功：**S2 从 45.7% 提升至 56.1%（+10.4%），S3 从 28.4% 提升至 55.7%（+27.3%）**！
  - 但这直接付出了 S1 的代价：共享的 421M Transformer 主干网络被大量的 S2 和 S3 梯度“反向拉扯”，在共享参数空间中形成了**正交乃至相反方向的梯度投影（Gradient Conflict）**。
  - 由于未引入任务专用的 Adapter、MoE 门控或梯度投影对齐算法（如 PCGrad），简单的均分损失函数使得 S1 的语义决策边界被稀释，导致 F04 的 S1 准确率在 Epoch 1 下滑至 63.64%。

### 归因 3：数据规模扩大带来的信噪比稀释（Data Scaling Dilution）
* **样本质量差异**：
  - 在 F06_S1（2.75 万条）中，所有数据均来自严格清洗的高置信度真实人工对战；
  - 在 F01~F04（从 48 万扩至 382 万条）中，为了实现所谓“全量覆盖”，引入了包含大量启发式规则补全、跨模型伪标签与合成数据的修复集。
* **小模型的容量饱和（Capacity Saturation）**：
  - 421M 参数的模型容量极其有限。当面对数百万条带有弱标注噪声的数据时，小模型缺乏足够的参数冗余去建立容错表征，弱标注噪声直接破坏了小样本时代建立的高精度决策超平面。
  - **现代大模型定律在此生效：质量（Quality）远比数量（Quantity）重要。粗糙扩增百倍数据反而劣于精细筛选的数万条金牌数据。**

### 归因 4：小样本验证集的统计采样方差（Statistical Sample Variance）
* 验证集仅 561 条样本，统计显著性区间极窄：
  - 1 条样本 = $1 / 561 \approx 0.178\%$；
  - 63.64%（357 条）与 68.09%（382 条）**仅相差 25 条样本**；
  - 66.84% 与 68.09% **仅相差 7 条样本**。
* 在小样本验证集上，随机 Mini-batch 采样顺序与 Dropout 扰动带来的波动，完全可以覆盖 7~15 条样本的涨跌。将 1~2 个百分点的波动解读为“模型能力质变或恶化”，在统计学上是不稳健的。

### 归因 5：单一指标审视的认知偏差（Single-Metric Blind Spot）
* 项目组此前在汇报中习惯将聚光灯全部打在 `S1 accuracy` 上，一旦 S1 没有突破 68%，就得出“训练停滞”的判断。
* **客观综合评估事实**：
  1. **多任务综合能力**：模型从原本只能做单纯的偏好选择（S2/S3 盲猜），进化为能够同时兼顾执行成功率预估与 Token 消耗阶梯预估的全面路由器；
  2. **训练损失**：全量流式训练 Loss 从 0.6300 稳定单调下降至 **0.4480**，表明模型对 382 万复杂样本的联合似然度在扎实提升；
  3. **校准误差（ECE/Brier）**：置信度校准曲线更加平滑，极端过自信错误大幅降低。

## 五、 给 Planning 审核团队的下一阶段行动破局提案（Actionable Proposals）

为了打破当前的瓶颈，让后续的资源投入产生确定性的指标飞跃，向 Planning 委员会提出以下四项工程与科研提案：

### 提案 A：评测集升维扩容与分层阶梯化（Priority: P0）
* **现状痛点**：561 条样本的小集合已产生天花板与统计方差双重干扰。
* **行动方案**：
  1. 将验证集扩充至 **3,000 ~ 5,000 条**；
  2. **分层评测**：分为「明显优劣局（Clear Win/Loss，置信度高）」与「势均力敌局（Close Battle，人评方差大）」，分别统计准确率；在明显优劣局上，目标应锚定 85%+；
  3. 引入基于代码和数学的客观确定性路由测试集（如 HumanEval/GSM8K 路由子集），以确定性指标取代单一的众包主观偏好。

### 提案 B：架构解耦与任务隔离（Priority: P0）
* **现状痛点**：421M 共享主干网络直接导致 S1 与 S2/S3 梯度剧烈冲突。
* **行动方案**：
  1. **专用 Head / Task LoRA**：主干网络提供基础语义特征，为 S1（模型路由）、S2（执行预测）、S3（长度感知）分别挂载独立的轻量 LoRA 或 Task-Specific MLP 分支，禁止 S2/S3 梯度污染 S1 的专属参数；
  2. **梯度投影对齐（PCGrad）**：在反向传播时，当检测到 $\mathbf{g}_{S1} \cdot \mathbf{g}_{S2} < 0$ 时，对梯度进行正交投影，消除负迁移拉扯。

### 提案 C：转向“精选数据蒸馏”，放弃粗放全量扩增（Priority: P1）
* **现状痛点**：从 3 万到 382 万的粗放扩充已被证明会稀释准确率。
* **行动方案**：
  1. 执行 **Data Curation > Data Scale** 路线；
  2. 基于当前训练出的 F04 模型计算所有样本的 Margin / Uncertainty，从 382 万样本中过滤剔除高噪声样本与模糊标签，仅筛选出 **Top 15%~20%（约 50万~80万条）高信噪比“金牌核心数据”**；
  3. 在清洗后的金牌子集上进行微调，追求 S1 突破 72%+。

### 提案 D：重塑评估基准：从单一分类准确率到“路由综合收益矩阵”（Priority: P1）
* **现状痛点**：将两个同样优秀的模型（如 GPT-4 与 Claude-3.5-Sonnet）中选错一个判定为 0 分，是不符合实际业务价值的。
* **行动方案**：
  1. 引入 **Cost-Quality Pareto Efficiency（性价比帕累托前沿）** 与 **Routed Win-Rate（路由后系统综合胜率）**；
  2. 哪怕 S1 准确率为 67%，只要它能成功将 80% 的简单查询路由给轻量小模型、20% 的硬核查询路由给顶尖大模型，且端到端用户满意度维持在 95% 以上、成本降低 60%，该路由模型就具有极高商业与学术价值。
