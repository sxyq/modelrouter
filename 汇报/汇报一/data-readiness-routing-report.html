MODEL ROUTING · DATA READINESS

训练数据够不够？
先看粒度，再看规模

这份报告把现有真实调用、Codex 本地记录和公开轨迹放在同一个决策框架里：它们足够支撑路由器的表示学习、成本预测和第一版模型；论文里的任务级选择结论仍需要少量同任务、多模型、多 effort 的受控执行结果。

统计时间跨度融合调用：2026-07-25 — 2026-09-19
Codex 监控汇总：截至 2026-09-22
单位：调用 / 会话 / token 分开表达
●
一句话判断：数据量已经足够做“预训练 + 成本画像 + 第一版路由器”，但调用量大不等于任务样本多。当前最稀缺的是同一任务在多个候选配置下的最终结果。

1. 已有数据规模：三种单位分别看

调用、会话和 token 不混在一根坐标轴上；每一项都保留自己的单位。

2. 融合调用的模型分布

CCH + SXYQ Blog，按模型归一后的调用量；它说明真实工作负载覆盖面，不代表任务级标签数量。

3. 推理档位使用分布

不同模型的同名档位不保证等价；这里先展示原生档位的实际使用量。

4. 数据能训练什么？

绿色 = 可直接使用；黄色 = 可用但需要补字段或统一口径；红色 = 目前缺失。
可直接使用部分可用当前缺失

5. 从“大量调用”到“可监督路由样本”的粒度差距

同一个 session 里的多次调用高度相关，不能直接当作同样数量的独立任务。

6. 推荐的数据使用路径

先利用已有记录学习工作负载和资源消耗，再用少量受控 episode 学习最终选择。

数据 → 模型 → 证据

1
公开轨迹 + 本地调用训练任务表示、工具行为、失败模式、token / 延迟 / 费用预测。
2
小规模配对执行固定任务、环境和 harness，只改变 model × 原生 effort，记录 resolved、总费用和调用数。
3
主动补采优先执行预测分歧最大、可能改变当前最优选择的任务。
4
训练快速路由器输出候选动作、成功概率、费用区间和置信度；低置信度时交给强模型。

建议的第一批规模

  • 100–300 个任务
  • 4 个候选模型
  • 每模型 1–2 个原生 effort
  • 约 800–2400 个 episode
  • 对不确定任务追加 300–600 条
  • 主指标：解决率、$/resolved、路由 regret、P90 费用、校准误差

7. 当前结论（分点）

① 数据量

够做第一版。85.9 万次融合调用、50.3B Codex token 和公开轨迹足以训练表示与资源预测模块。

② 数据质量

任务级标签不足。目前缺少稳定的 task_id、resolved、跨模型对照和完整 total_cost，不能直接训练最终选择头。

③ 模型规模

先小后大。先用 GBDT / MLP 或 30M–100M 编码器；高质量配对 episode 上来后再尝试 100M–300M。

④ 推理档位

按模型原生处理。动作定义为 (model, native_effort)；统一预算只做近似比较，不把不同模型的 high 视为同一档。

⑤ 真实数据

可以使用。CCH / Blog 提供成本先验，Codex JSONL 提供轨迹和 effort，公开数据提供表示与失败模式。

⑥ 论文证据

核心结论要靠受控对照。已有日志用于预训练和成本建模；同任务多配置的少量重放用于证明路由有效。

数据口径：CCH + SXYQ GPT 融合汇总为 859,549 次调用、79 条模型×档位记录、11 个归一模型；CCH 费用为 USD，Blog 使用 quotaUnits，二者没有直接相加。Codex 本地 Token Monitor 汇总为 3,403 个 session、322,031 条消息、约 50.3B token、约 $3,083.73；JSONL 目录共 772 个文件，其中 551 个出现 token 记录，合计 61,870 条 token_usage_record。报告未读取或展示 prompt、回复正文、密钥、IP 等敏感内容。本轮只新增本报告文件，未修改原始数据。
