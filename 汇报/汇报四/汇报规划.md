## 1. 汇报主线和听众应带走的结论

1. **做成了什么**：已有真实 Single-Agent / Harbor 执行、可替代的 Laya/Kev、S1/S2/S3、T/M/H、模型与原生 Effort 注册、Provider/AA/教师、历史训练和缓存记录。
2. **真正测到了什么**：89 题中 Agent 已尝试 29 题，22 题至少一次官方 Reward；最近 49 次尝试有 33 有效 Reward，21 个 1、12 个 0；新 K=3 三题对照尚未证明训练版优于原始版，更未得到完整现金净收益。
3. **为什么要调整研究定位**：JevAgentHarness 已覆盖轻量 Agent 决策和 Strong/Fast 逐步路由；Whose turn 已覆盖状态历史与 Provider Prompt Cache 的切换经济性。不能把两篇直接组合为所谓全新方法，也不能因为重叠就放弃已有成果。
4. **讨论什么**：六条**互相独立**的论文调整路线；至少明确一条可能成立的新增科学问题、相近工作、现有资产复用与最少关键证据，研究结果尚未预设。

## 3. 两篇核心论文的笔记格式（照汇报二范式）

每篇的 `笔记/<paper>/笔记.md` 统一包含：文献元信息（版本/作者/来源/PDF）；一句话定位；科学问题；问题定义与决策边界；原文 Figure 的编号和物理页；具体算法/训练/输入输出；真实实验设置与结果；作者局限；开源实现核对；和 V9 **重叠 / 差异 / 仍需证明**；本次 PPT 可引用的主图和图表。没有原文证据的字段保留“待核”，不填猜测。

- JevAgentHarness：区分 AgentDecision 的离散委派训练 **与** 其独立 Strong/Fast Coding Agent 路由能力。早期 `JEV深度调研报告.md` 讲的是 TypeSafe Jev/生态，不是此篇论文专门笔记。
- Whose turn：已有 `our-project/literature/notes/whose-turn-is-it-2610.19292.zh.md`，直接引用和补原文图；强调 user-turn、zero-shot、二候选、Provider cache billing，非异构物理 KV 共享。

其他论文采用一页/几张卡片，而不是给每篇重复制作三页完整讲解；可复用汇报二的五篇详细笔记。
