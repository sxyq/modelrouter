# JevAgentHarness：Agent 决策模型的评测、部署、训练与强弱模型委派

> 原文作者：Kunlun Zhu, Tao Feng, Xu Han, Heng Wang, Ling Yang, Xiangru Tang, Jiaxuan You, Heng Ji。2026-10-15 arXiv 预印本。原版 PDF 在仓库 `our-project/external/research/papers/60_JevAgentHarness_Benchmarking_Deploying_and_Training_Decision_Models.pdf`，由 [作者开源仓库](https://github.com/JevAgentHarness/JevAgentHarness/blob/main/paper/JevAgentHarness.pdf) 的原始二进制复制。作者方法图及结果图见 [原图索引](../../图片/论文原图/README.md)。

## 0. 一句话定位
它的**主线**是让 decision model 处理 Agent 中工具选择、参数选择、结束判断等离散决策，在低置信度时交还大 LLM；同时作者的独立路由代理又在 Terminal-Bench 上实际开展了 **Strong/Fast 每步模型路由**。两者都必须谈，不能把后者说成论文完全没有的功能。

## 1. 科学问题与关键认识
孤立多选题准确率不能推断真实 Agent 完整任务成功率：状态随动作、工具和错误持续演化；某一步选错后会访问训练数据没有覆盖的状态。论文通过 AgentDecisionBench 连接孤立问题、保存状态和真实 Agent 控制，分析离线准确率与闭环后果之间的差距。论文摘要给出的实例：孤立问题最高准确率决策模型在某组 Agent 任务中只完成 69.5%；没有适配阈值的工具委派令任务成功率下降 19.0 个百分点。这不是我们的结果。

## 2. 研究对象、动作与三种证据层
- **Decision 模式**：从少数合法动作中选一个，例如哪个工具、用什么参数、任务是否结束。该动作不是开放式生成下一个长答案。
- **AgentDecisionBench**：分别检测孤立决策、从 Agent 保存状态提出的决策题、模型真实接管 Agent 时的终局；防止用离线准确率取代任务成功。
- **DecisionGym / 状态分布**：Agent 的历史工具观察和先前错误会改变后续状态分布；控制成功率与能否在自己造成的错误状态继续作合理选择密切相关。
- **完整 Agent 结果**：包含本地/工具步骤、回退、LLM 费用和真实 task completion。不同实验组不能直接用百分数相除作跨环境比较。

## 3. 核心方法：JevAgentHarness
1. 在某个具体离散选择点，将当前 Agent 状态、问题和合法候选编码供决策模型评估。
2. 使用任务相关的置信度判断能否委派；作者在 Agent 自己到达的轨迹上为选择类型校准阈值，而不是只用统一的离线准确率阈值。
3. 置信度低则交给原 LLM 决定；决定完成任务和异常情况按安全回退路径处理。
4. 继续执行工具并观测实际状态，形成闭环；动态状态分布是主要挑战，不是简单“更快做单选题”。
5. **另有工程代理模型路由**：终端用户在 OpenAI-compatible 代理前使用逻辑模型，代理根据小决策模型判断步骤难度，选择 Strong 或 Fast。作者在 README 明确保护第一步和完成判断交给 Strong，并在错误时回退。该 Strong/Fast 功能与工具选择的 AgentDecision 训练应分开叙述。

## 4. 训练：AgentDecision-4B
研究动机是通用决策模型在自己错误造成的状态上泛化不足。作者从 Agent 自身轨迹抽取这些状态、使用 Jev 的输出形成训练标签，得到 AgentDecision-4B；另有 0.8B 变体与不同对照。关键增量是 **on-policy 访问到的状态与阈值适配**，而不是“用了 4B”本身。官方项目提供训练脚本、决策基准与 coding-agent-decisions 轨迹材料；部分模型/数据标注 CC BY-NC 4.0，不能不经审查混进我们的训练集。

## 5. 原论文核心实证
### 5.1 决策模型与真实任务
论文报告离线最准模型仅完成 69.5% 的特定 Agent 任务；未经适配阈值时工具选择委派使成功率下降 19.0 percentage points。使用 AgentDecision-4B 在未见任务上完成 91.5%，对应 Jev 为 82.0%；在相似任务上，作者报告采用其训练法的 4B 决策模型可节省 81.1–89.0% 成本、加速最高 2.5x，同时成功率损失少于 3 个百分点。实验环境和比较组不同，数字不能混成同一张表的单次实验。

### 5.2 Coding Agent Strong/Fast 路由（官方仓库 74 题）
设置：Terminal-Bench 2.0，各 Harness 74 道 held-out task、每配置一遍；Strong=Gemini 4 Argon（high thinking），Fast=Gemini 3.5 Flash-Lite；决策模型 Jev，阈值 τ=0.75。作者代理按参考费率、缓存读取价格以及 decision-model 调用计算 LLM 账单。

| Harness | 成功率 Strong→Routed | 单题模型费 Strong→Routed | 平均任务时长 Strong→Routed |
|---|---:|---:|---:|
| mini-swe-agent | 66.2%→63.5% | $0.91→$0.33（-64%） | 13.7→7.9 min |
| pi | 52.7%→56.8% | $0.62→$0.42（-31%） | 11.3→10.8 min |
| DeepSeek Harness | 66.2%→66.2% | $0.94→$0.68（-28%） | 13.4→11.4 min |
| Terminus-2 | 27.0%→41.9% | $0.11→$0.14（成本升） | 22.6→16.1 min |

注意：成功率差的置信区间较宽；成本节省不能被解释为所有配置都无显著质量变化的证明。和我们的 Harbor 2.1 / 不同模型池不可横向直接合表。

## 6. 竞争基线与局限
Strong-only；不同 Fast 档位和阈值；固定规则或无需决策模型的委派策略；AgentDecision 的训练版与现成 Jev 比较。局限包括错误传播、阈值需依赖部署轨迹校准、候选 Fast 价格差/Prompt Cache/任务难度改变盈利空间，以及环境、模型和预算条件并非与 V9 相同。

## 7. 与 ModelRouter V9 真正的重叠
**明确覆盖**：Agent 内决策模型、真实执行状态、低成本路由、Strong/Fast 每次 LLM-call 选择、完整任务成功率与代理费用。
**尚未等同**：V9 的多个真实候选模型 × Provider Native Effort 合法联合动作、Laya/Kev 独立监督体系、T/M/H 和教师/缓存具体信息；这些目前仍只是实现层差异，**不是自动成立的论文创新**。
**最直接应比**：Jev Strong/Fast 在同任务相同 Harness 中的可执行改编基线；固定模型、Laya/Kev 原始/训练版；按完整任务成功/已知费用/未知费用分层比较。不可借不同 Benchmark 和模型型号来回避竞争。
