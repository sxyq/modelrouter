# Whose turn is it?：有状态 Agent 的轮次级历史路由与缓存切换

> 作者：Anikesh Parashar, Avik Dutta, Vashu Chauhan, Sumit Gulwani, Priyanshu Gupta, Hosein Hasanbeig, Vu Le, Ashish Tiwari, Jack Williams。arXiv 2610.19292v1（2026-10-13）。详细依据：本仓 [既有中文研究笔记](../../../../our-project/literature/notes/whose-turn-is-it-2610.19292.zh.md)。**当前只取得原始 PDF 来源链接，未取得可验证的原版 PDF 文件及 PDF 真实截图，因此不得声称已经裁剪原论文 Figure。**

## 0. 一句话定位
用户每轮请求可能引起多个内部 LLM/工具调用，任务难度依赖前面轮次产生的状态。作者提出 **zero-shot、二候选、user-turn 级**有状态路由，并分析 Provider Prompt Cache 的模型切换成本与方向不对称。

## 1. 为什么单请求路由不足？
普通 prompt-router 只观察当前问题；有状态表格 Agent 必须记住之前的工作簿修改、工具错误和上次决策。极短的“继续/重试”可能难度取决于此前失败或工作簿状态。模型切换还可能丢掉对旧物理模型可复用的对话前缀缓存，从而改变经济收益。因此模型选择要同时观察质量机会和可能的缓存损失。

## 2. 决策边界和候选
- Turn 定义：用户的一次请求以及该轮内部完整的 Agent/工具循环。
- 决策时点：**每个用户轮次开始之前**选择；通常一轮内部保持所选候选模型。
- 候选：便宜模型与昂贵模型；还研究同模型不同 reasoning effort、同提供商不同模型、跨提供商模型对。
- 主要策略：零样本路由器有历史/无历史、cheap→expensive escalation、expensive→cheap de-escalation、随机、固定。
- 不训练 V9 式的监督 Router；并未实测异构 K=3/5/7 的统一 Model×Native Effort 多类选择策略。

## 3. 核心方法与路由逻辑
先读取当前用户输入 u_t，按配置加入历史 h_t（前面轮次的工具观察、错误、工作簿及决策），交给 zero-shot LLM router π 得到此轮 cheap 或 expensive 的选择。模型完成整轮工具交互，变化后的工作簿状态被下一轮读取。Escalation/De-escalation 的基线并不是和这个零样本规则同一件事：它们对当前轮次采用先低后高或先高后低的调用方向。

## 4. Prompt Cache 不是物理 KV 共享
论文缓存分析关注 Provider 计费和 prefix reuse：当前模型可复用自己既有的 conversation prefix，切换到另一个模型后不应默认复用旧模型的会话专属缓存；另一方面，新模型自己的 system/tool 公共前缀仍可能复用。所谓 switching cost 是两种缓存价格、长度、调用次数、模型方向的联合作用，既不是恒定模型切换罚金，也不是跨模型 KV 张量映射。

### 4.1 回本含义
作者给出闭式 break-even 关系：考虑切换一次导致的额外输入费，后续便宜模型每次调用相对昂贵模型能省的输入费随请求次数积累。在论文具体价格/缓存假设下，昂贵→便宜可能约两次后续调用即可回收；便宜→昂贵在评测条件下无法通过这一输入差价回收。这只是作者设定下的分析结果，不是跨模型和跨场景的定理。

### 4.3 基于原文的额外机制边界
作者 per-turn zero-shot router 在一轮开始前调用一次；**escalation/de-escalation 对照策略可在轮次内部切换**。正文对“由 working model 自行判断”与表格/流程图中“router 决定升级”的表述有歧义，因此组会不把这组基线的内部决策归属讲成已彻底核定。完整报告可以说明其按 cheap-first / expensive-first 执行的特征。

## 5. 实验设定
- SheetCopilot 多轮变体：**112 个任务**，平均 **2.88 turns**，最多 **7 turns**；SpreadsheetBench 2：**221 个任务**，平均 **4.76 turns**，最多 **6 turns**，排除了 debugging 类型。带持续工作簿和跨用户轮次依赖；由最终工作簿评测通过率。
- 对不同模型对研究历史访问、卸载比例、routing policy、缓存与费用。
- 指标包括任务 Pass、按整轮/整任务的模型调用费用、不同长度会话及切换成本。
- 不能用它的结果代替 Terminal-Bench Coding Agent 的实际成功/USD/延迟；也不能把 spreadsheet 轮次级设置称为生成级委派。

## 6. 原文结果（逐项标条件）
1. SheetCopilot 在匹配 cheap-turn offloading 水平下，current-only **25.0%** vs history-aware **28.3%**（+3.3 percentage points），两版本廉价轮次占比约 **23.3% vs 22.7%**；不能说所有工作负载都提高 3.3 点。具体三对在 SheetCopilot 的增量分别 +5.4 / +2.7 / +1.7pp，不能把这个观察外推到 SSB2。
2. **限制性反例（必须保留）**：SpreadsheetBench 2 上 Opus high/low 这对候选模型，**history-aware 32.4% vs no-history 35.8%**，反而下降 **3.4pp**。因此论文摘要的“每个模型对都改进”不能解释成在两数据集所有实验组合都成立；相应数字可从作者原文 Table 4 再次核对。
3. 作者跨两种不同长度与工作负载的表格任务观察 Haiku 相对 Sol 的 per-task 成本优势 **6.8× → 3.2×**；含工作负载差异，不宜归因于“仅会话变长”。
4. 缓存回本：贵→便宜约两次后续 LLM 调用内回本；反方向在所设条件下不回本。是参数化价格推导，非物理 KV 迁移实测。
5. 某些模型对中便宜模型已有足够甚至更高的实际质量，固定使用便宜模型比任何动态复杂 Router 更经济；这一结果是对路由必要性的约束。
6. 论文部分附录 cost 表格注明 **excluding router call**；对比我们的总 Episode 成本必须重新统一口径。

## 7. 局限与和我们问题的重叠
**直接覆盖**：历史信息影响模型选择、stateful agent 的质量—成本、Prompt Cache 影响切换、模型对影响路由收益、不能盲信静态价格差。
**未直接验证**：在 Mini-SWE-agent 内逐次生成重新路由、超过二候选 K 的可训练模型池、在真实软件修复中因失败恢复产生的完整任务切换净价值。
**仍需证明的差异**：我们的 T/M/H、AA/teacher、模型身份和 Native Effort 若不能产生额外任务质量或费用增量，就只能算实现范围差异。
