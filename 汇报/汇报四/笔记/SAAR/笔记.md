# SAAR：长会话 Agent 的模型驻留、切换边界与缓存结算

> 作者：Xunzhuo Liu、Bowei He、Huamin Chen、Haichen Zhang、Andy Luo 与 vLLM Semantic Router Team。2026-06-02 vLLM 官方技术博客，**不是 arXiv 研究论文**。源码原文见 [官方 GitHub Markdown](https://github.com/vllm-project/vllm-project.github.io/blob/main/_posts/2026-06-02-session-aware-agentic-routing.md)。

## 0. 一句话定位
保持现有语义模型选择器不变，增加一个 session-control 层，确保工具循环和不可移交 Provider 状态下不乱切模型；在 idle / task drift 边界允许重新选择；根据热 Prefix Cache 和模型价格估计切换成本，并保留可重放路由解释。

## 1. 问题是什么
纯 prompt-level Router 对“继续”“工具返回”“再试一次”缺乏完整历史认知，很容易在请求级看来划算、在 Agent 连续性上却错误：工具结果被送给不曾发起工具的模型；不可迁移的 provider continuation id 到了错误后端；暖缓存丢失；逻辑模型 auto 的物理后端不透明。

## 2. 方法五部分
1. **Router memory** 保存上一次物理模型、相中决策、phase、切换次数、闲置时间、缓存证据与 replay 元数据。这不是应用程序自身的长期记忆。
2. **Hard locks**：工具调用尚未返回或存在不可移交的 Provider continuation state 时强制保持当前物理模型，正确性先于省钱。
3. **Reset boundaries**：idle timeout 或决策偏移（drift）使模型重选合法；不是永远固定模型。
4. **Switch economics**：保留模型 warm prefix 的价值、历史切换成本和未来会话长度影响切换阈值，考虑 cached-input 与普通输入费的 checkout 差。
5. **Replayable traces**：记录为何锁定、继续、重选以及物理后端证据，方便解释逻辑模型。

## 3. 与物理 KV 的区别
作者用 prefix-cache-aware 价格和物理模型身份做切换决策；模型驻留/缓存命中证据区分逻辑路由和真实 serving 后端。不能从其 switch-cost 模型推出跨模型物理 KV tensor 被直接共享。V9 报告的 provider cache tokens 与这一假设的因果推导更不能混同。

## 4. 三层评价
**21,600 确定性 turns**：多个合成 session 的 policy matrix，用于隔离控制逻辑，并非 21,600 个真实 Terminal-Bench Agent 任务；对比 Single-turn、Sticky、Initial SAAR 和 Full SAAR。
**有结构的确定性 Agent traces**：用模拟工具观察与明确 final-answer scoring 观察策略质量变化，但不能直接等同于 Harbor 真实软件修复成功。
**2,896 实际 ROCm 请求**：真实 OpenAI-compatible serving 路径的协议与连续性核验；报告观测到 0 continuity violation，不等于在真实 Benchmark 上证明了完整任务成功率收益。

## 5. 官方结果
| 策略 | 切换次数 | Unsafe switch | 估计成本减少 | 相对质量变化 |
|---|---:|---:|---:|---:|
| Single-turn | 9709 | 3836 | 0% | +0.0000 |
| Sticky session | 340 | 0 | 98.65% | -0.1433 |
| Initial SAAR | 1810 | 200 | 70.92% | -0.0122 |
| Full SAAR | 2011 | 0 | 78.71% | -0.0453 |

相对 Single-turn，Full SAAR 减少 79.29% 切换。消融中去除 tool lock 引入 760 次不安全切换；去除 provider-state lock 引入 200 次；去除 prefix frontier 费用约束降低其报告的成本节省。上述百分比来自确定性 policy matrix 的**估计成本**，不能标为真实供应商已付账单。
真实 ROCm 分组：2048+768+80=2896 请求，观察到 0 continuity violation；p95 overhead 分别 6.181、26.805、283.463 毫秒，idle 组含真实等待，需与热路径分开解读。

## 6. 和 V9 的重叠
**已有明确先例**：session continuity、tool-loop 守护、safe reselection、prefix cache 决策价格和日志可解释。因此 V9 不能仅凭“缓存感知 Sticky”“事件触发重新路由”宣称新颖。
**不同问题**：SAAR 更偏 serving policy 的安全连续性和 session cost；V9 的独立目标仍需在真实 Coding Agent 上体现质量—总费用的可测增益、合法 Model×Native Effort 选择与多候选复杂性。
**局限**：合成 session 估价及 ROCm 连续性不构成 Harbor 成功/失败或完整现金费用的相同 benchmark；应分别对照而不是直接比百分比。
